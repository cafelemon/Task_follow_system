层级	推荐
前端	React + TypeScript + Vite + Ant Design / Ant Design ProComponents

## 七、权限别一开始做复杂，但底座要留好

你这个系统最容易炸的地方不是页面，也不是数据库，是权限。

建议第一版采用：

RBAC + 任务关系权限

也就是：

RBAC

用户有角色：

系统管理员
总经办/秘书
母任务负责人
部门负责人
任务负责人
子任务执行人
观察角色
信息中心维护人员

任务关系权限

再判断用户和任务的关系：

是不是母任务负责人
是不是部门任务负责人
是不是子任务执行人
是不是所属部门负责人
是不是有全局查看权限

不要只靠角色。

## 八、飞书接入建议

第一版别把飞书做太深，先做三个能力：

open_id 绑定用户
机器人发送提醒
消息卡片跳转 Web 页面

这个参考/Users/jiafei/workspace/feishu_fastgpt_bridge项目，里面有一套飞书接入的逻辑和系统，当然我们不能完全照搬和复用，因为我们涉及到权限更加复杂，基本上每个人都有自己的权限，我的想法是先靠open_id加姓名来锁定账号，不要靠飞书带出来的部门信息（飞书的部门信息不全，很多人是跨部门的只带出来一个）我们有了姓名账号后相当于在我们任务系统里面重新为他们每个人设置所属部门，设置相关角色，权限上面说了肯定是不只是靠角色，也需要靠跟任务的划分上，好几个角色的时候采用各角色最高权限的汇总也就是权限并集，这个后面再细调第一版先做个打通。

可以参考目前过渡产品飞书多维表格：任务跟踪表的母任务，任务，子任务以及相关的权限设计。
