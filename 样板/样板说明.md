# 公司任务推进与周更新跟踪系统  
# 静态页面样板说明 V0.1

## 1. 样板用途

本样板用于展示「公司任务推进与周更新跟踪系统」的初步页面形态和业务结构。

当前页面为飞书妙搭生成的静态原型，主要用于验证以下内容：

1. 系统整体信息架构是否合理。
2. 各页面模块是否覆盖公司任务管理闭环。
3. 管理层、任务负责人、部门负责人、执行人等角色是否能快速理解系统用途。
4. 后续前端开发、后端建模、数据库设计和权限设计是否有可参考的页面骨架。
5. 是否能够替代目前飞书多维表格中任务录入、拆分、每周更新、提醒、看板展示等工作流。

当前样板不代表最终产品设计，不涉及真实数据、不涉及真实权限、不涉及真实飞书 open_id 绑定，仅作为第一版产品形态参考。

---

## 2. 系统定位说明

本系统定位为公司级任务闭环跟踪平台。

系统不是普通待办工具，也不是单纯项目管理看板，而是围绕公司级任务的「提出、拆分、执行、每周汇报、风险跟踪、会议查看、历史追溯、通知提醒」形成完整闭环。

当前样板体现的核心思路包括：

1. 公司任务按层级管理。
2. 战略目标与具体任务建立关联。
3. 母任务由公司或管理层确立。
4. 部门任务用于承接母任务。
5. 子任务由具体执行人推进。
6. 执行人按周填写进展。
7. 每次周更新形成历史记录，不覆盖旧数据。
8. 管理层可集中查看未更新、风险、逾期和需协调事项。
9. 飞书通知作为提醒入口，Web 页面作为主操作入口。
10. 权限根据角色、部门和任务关系进行控制。

## 4. 页面模块说明

## 4.1 工作台

工作台是系统首页，用于快速查看公司任务整体状态。

当前样板包含四个核心统计卡片：

1. 进行中母任务：18
2. 本周待更新子任务：42
3. 存在风险任务：7
4. 已逾期任务：5

下方包含两个核心区域：

### 本周任务更新进度

展示本周任务填报情况：

1. 应更新任务数。
2. 已更新任务数。
3. 未更新任务数。
4. 更新完成率。

当前样板使用环形图展示更新完成率，同时在右侧列出应更新、已更新、未更新数量。

### 本周风险概览

展示不同风险等级的任务数量：

1. 高风险。
2. 中风险。
3. 低风险。

当前样板使用三张风险卡片展示风险等级、数量、占比和简单进度条。

### 当前评价

工作台的方向正确，能够帮助管理层快速看到整体情况。

后续需要进一步确认：

1. 统计口径是否以子任务为准，还是以部门任务、母任务为准。
2. 「本周待更新子任务」是否应该改为「本周应更新子任务」。
3. 风险统计是否需要区分「主动上报风险」和「系统判定风险」。
4. 逾期任务是否应包含已完成但曾经逾期的任务。

## 4.2 战略目标

战略目标页面用于展示公司顶层目标，以及目标与任务之间的关联。

当前样板展示了三个战略目标：

1. 建设临床数据智能平台。
2. 推进企业数字化转型。
3. 完善质量与合规体系。

每个目标卡片包含：

1. 目标名称。
2. 目标说明。
3. 关联母任务数量。
4. 整体进度。

### 当前评价

战略目标页面方向正确，可以作为公司级任务的顶层入口。

后续需要进一步确认：

1. 战略目标是否由总经办维护。
2. 战略目标是否需要年度、季度维度。
3. 一个母任务是否只能关联一个战略目标，还是可以关联多个战略目标。
4. 战略目标进度是人工填写，还是由下级任务自动汇总计算。

## 4.3 母任务管理

母任务管理页面用于集中展示公司级核心任务。

当前样板使用卡片形式展示母任务，包括：

1. 母任务编号。
2. 母任务名称。
3. 责任部门。
4. 负责人。
5. 截止时间。
6. 整体进度。
7. 下辖子任务数量。
8. 当前状态。

当前示例包括：

1. 临床数据智能管理系统建设。
2. NAS 数据资产迁移。
3. AI 知识库资料入库。
4. 医患协同平台需求梳理。
5. 飞书任务提醒机制建设。

### 当前评价

母任务页面的卡片形式直观，但如果任务数量较多，后续可能需要支持列表视图、筛选、排序和批量导出。

后续需要进一步确认：

1. 母任务是否一定由总经办创建。
2. 母任务负责人和责任部门是否必填。
3. 母任务下是否直接挂子任务，还是必须先拆为部门任务。
4. 母任务进度是否由下级部门任务或子任务自动汇总。
5. 母任务状态是否允许人工修改。

1. 部门任务是母任务拆解后的一级承接对象，还是只是统计视图。
2. 部门负责人是否可以在本页面继续拆分子任务。
3. 是否需要展示跨部门协同任务。
4. 部门完成率如何计算。
5. 部门任务是否允许多个负责人。

每周更新页面用于执行人填写结构化周进展。

当前样板包含：

1. 子任务选择。
2. 本周状态。

4. 本周完成内容。

6. 风险/卡点。
7. 是否需要协调。
8. 附件上传。
9. 提交按钮。
10. 保存草稿按钮。

页面顶部有提示：

每周更新不是覆盖历史，而是形成一条新的历史记录。每次提交都会追加到时间线中，确保过程可追溯。

### 当前评价

每周更新页面是本系统最关键的页面之一。

后续需要进一步确认：

1. 每周更新是否每个子任务每周只能提交一次。

3. 修改是否生成修订记录。

5. 附件是上传到系统服务器，还是存储到 NAS。
6. 未更新是否自动触发飞书提醒。
7. 周更新是否需要部门负责人审核。

## 5. 当前样板整体评价

当前样板已经具备系统雏形，整体风格清爽，页面结构完整，能够表达任务闭环管理的方向。

优点包括：

1. 页面结构完整，覆盖主要业务模块。
2. 导航清晰，符合企业后台系统使用习惯。
3. 工作台具备管理驾驶舱感觉。
4. 周更新页面体现了“追加历史，不覆盖历史”的核心设计。
5. 会议看板聚焦风险、未更新和协调事项，适合管理层使用。
6. 时间线页面能体现可追溯能力。
7. 通知记录页面能体现飞书提醒闭环。
8. 权限页面已经具备角色矩阵雏形。

当前不足包括：

1. 任务层级关系还不够清楚。
2. 母任务、部门任务、子任务之间的边界需要进一步收紧。

5. 每周更新页面需要补充提交规则、修改规则和审核规则。
6. 会议看板需要明确是否自动生成。
7. 风险与逾期需要区分系统自动判定和人工上报。
8. 权限页面需要进一步产品化。
9. 当前样板缺少任务详情页或详情抽屉。
10. 当前样板缺少新建母任务、拆分部门任务、创建子任务的表单流程。

## 6. 后续重点修改方向

下一版样板建议重点修改以下内容：

### 6.1 明确任务层级

建议固定为：

战略目标  
→ 母任务  
→ 部门任务  
→ 子任务  
→ 每周更新  
→ 历史事件

需要避免母任务直接下挂子任务、部门任务和子任务混用的问题。

### 6.2 增加任务详情页

任务详情页应成为系统核心页面，建议包含：

1. 基础信息。
2. 层级路径。
3. 当前状态。
4. 负责人和执行人。
5. 最新周更新。
6. 历史周更新。
7. 风险记录。
8. 协调事项。
9. 附件。
10. 时间线。

### 6.3 增加任务创建与拆分流程

建议补充三个关键表单：

1. 新建母任务。
2. 拆分部门任务。
3. 创建子任务。

这三个表单会直接影响后端数据库设计。

### 6.4 优化工作台

工作台建议分角色展示：

1. 管理层看到全公司任务概览。
2. 部门负责人看到本部门任务概览。
3. 任务负责人看到自己负责的任务。
4. 执行人看到自己本周需要更新的任务。

### 6.5 强化每周更新闭环

每周更新需要形成完整闭环：

1. 周期开始。
2. 飞书提醒。
3. 执行人填写。
4. 系统记录。
5. 未填报催办。
6. 风险进入风险池。
7. 协调事项进入会议看板。
8. 周期归档。

### 6.6 优化会议看板

会议看板建议聚焦管理动作，不要只是展示任务。

建议固定栏目：

1. 本周必须决策事项。
2. 本周高风险任务。
3. 本周未更新任务。
4. 需要跨部门协调事项。
5. 本周完成事项。
6. 下周重点关注事项。

## 8. 当前版本结论

当前静态样板可以作为 V0.1 产品原型参考。

它已经证明该系统不应该继续停留在飞书多维表格形态，而应该作为一个独立 Web 系统建设。

下一步不建议立即进入开发，而是应先围绕当前样板完成以下工作：

1. 明确页面需要删除、保留、合并的模块。
2. 明确任务层级和字段。
3. 明确不同角色的真实使用路径。
4. 明确每周更新规则。
5. 明确风险、逾期、协调事项的流转方式。
6. 明确第一版 MVP 范围。
7. 再根据确认后的页面和流程，编写数据库模型与接口设计。
