# AI Coding Agent 工作协议

## 1. 文档用途

本文档写给 Codex、Cursor、Claude Code 或其他 AI Coding Agent，用于约束本项目的协作方式、文档维护、代码修改、验证和工具使用。

## 2. 基本原则

- 以最终效果最好为最高优先级，不因为现有工具不方便就降低方案质量。
- 如果需要新工具、依赖、脚本或服务来更好完成任务，应说明原因并申请安装或启用。
- 新功能和重要改动先看文档，再改代码。
- 修改前先确认当前文件状态，保护用户已有改动。
- 不做无关重构，不扩大任务范围。
- 每次完成阶段性工作后，更新进度和必要决策。

## 3. 开始工作前必须阅读

进入本项目开发前，至少阅读：

- `docs/00_overview.md`
- `docs/01_prd.md`
- `docs/02_roadmap.md`
- `docs/03_architecture.md`
- `docs/04_acceptance_checklist.md`
- `docs/06_progress.md`
- `docs/07_decisions.md`

如果任务涉及 AI Agent 自身工作方式，也需要阅读本文档。

## 4. 文档维护规则

新项目和重要阶段先写文档。`docs/` 目录采用小写编号命名：

- `00_overview.md`
- `01_prd.md`
- `02_roadmap.md`
- `03_architecture.md`
- `04_acceptance_checklist.md`
- `05_ai_coding_agent_guide.md`
- `06_progress.md`
- `07_decisions.md`

维护规则：

- 文档文件名不要使用大写。
- 新增决策写入 `07_decisions.md`。
- 阶段进展写入 `06_progress.md`。
- 产品范围变化同步更新 `01_prd.md` 和 `02_roadmap.md`。
- 架构、数据模型、部署方式变化同步更新 `03_architecture.md`。
- 验收项变化同步更新 `04_acceptance_checklist.md`。

## 5. 修改代码前的工作流

每次修改代码前：

1. 查看当前目录结构和相关文件。
2. 查看 git 状态，识别用户已有改动。
3. 阅读相关文档和现有实现。
4. 明确本次改动的目标、范围和验收方式。
5. 再进行最小必要修改。

不要因为实现方便而绕开既定产品口径，例如：

- 不要把 Base 重新当作主业务系统。
- 不要用覆盖字段代替周更新历史记录。
- 不要要求用户手填系统应该生成的编号。
- 不要把复杂操作塞进飞书卡片，复杂操作应跳转 Web 页面。

## 6. 代码实现原则

- 后端优先保证数据正确、权限正确、历史可追踪。
- 前端优先保证业务路径清楚、页面稳定、信息密度合适。
- 接口优先表达业务对象，不把前端表格字段直接当作长期数据模型。
- 校验必须发生在保存和触发自动化之前。
- 任务事件、通知记录、周更新记录要为后续审计和排查预留。
- 附件优先存储到 NAS 或文件存储，数据库保存元数据。

## 7. UI 实现原则

- 系统是公司级内部工作台，不是营销页，也不是临时表格工具。
- 默认采用左侧导航、顶部状态区、主内容区。
- 卡片只用于任务、统计项和操作模块，不堆叠装饰卡片。
- 表格用于扫描和对比，不作为唯一交互形态。
- 时间线是任务详情页核心能力。
- 状态标签统一，颜色表达稳定。
- 页面按身份展示操作，不展示用户无权操作的按钮。

## 8. 验证规则

完成开发后，应根据改动范围选择验证方式：

- 文档改动：检查文件名、标题、交叉引用和内容完整性。
- 后端改动：运行单元测试、接口测试或最小可复现请求。
- 前端改动：启动页面并检查关键流程和视觉状态。
- 权限改动：至少验证有权限和无权限两类用户。
- 飞书改动：验证卡片内容、跳转链接、推送记录和失败处理。
- 导出或附件改动：验证文件生成、路径、权限和下载。

如果不能运行测试或验证，要在最终回复中明确说明。

## 9. 进度和决策记录

当完成一个阶段或做出重要取舍时：

- 在 `06_progress.md` 记录完成内容、验证结果、未完成事项和下一步。
- 在 `07_decisions.md` 记录决策背景、决策内容和影响。

决策记录应简洁，但要能让后来接手的人理解为什么这么做。

## 10. 工具使用

- 搜索文件和文本优先使用 `rg`。
- 批量阅读文件时可并行读取。
- 修改文件优先使用可审计的 patch。
- 如果需要安装依赖、启动外部服务、访问网络或使用新工具，应说明用途并按环境要求申请。
- 不要绕过权限限制，不要执行破坏性命令。
