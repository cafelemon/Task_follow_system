# 任务跟踪系统角色化使用引导审核说明

## 1. 审核目的

本文档说明 `2.3.4` 起的角色化引导框架，供管理层审核角色口径、引导层级和已完成角色的引导内容。`4.7.1` 已将总经办/秘书指南更新到当前工作台与会议看板口径，并将前端指南配置从 `App.tsx` 拆到 `features/guides`。

使用引导不替代制度培训。它只负责帮助用户理解系统框架、找到与职责相关的入口，并在首次使用具体板块时掌握基本审阅或操作方法。

## 2. 五类引导身份

| 引导身份 | 主要适用人员 | 核心职责 |
| --- | --- | --- |
| 总经办会议相关 | 总经理、总经办秘书 | 审阅公司任务推进、风险、逾期和会议决策事项 |
| 部门负责人 | 具有部门负责人角色且已配置所属部门的人员 | 查看本部门牵头母任务，拆分和管理相关部门任务 |
| 任务负责人 | 部门任务负责人 | 拆分子任务、指定执行人、跟踪进展和风险 |
| 子任务执行者 | 子任务执行人 | 执行任务、提交周更新、登记发现的风险 |
| 观察者 | 获得观察角色的人员 | 全局只读审阅、任务追溯和会议准备 |

多身份用户只展示一套主引导，优先级为：

`总经办会议相关 > 观察者 > 部门负责人 > 任务负责人 > 子任务执行者`

系统管理员和信息中心维护身份不再单独形成业务引导。若技术管理员同时拥有业务角色，则按业务角色展示。观察者优先于任务负责人和执行者，是为了覆盖“以审阅为主、同时兼任具体任务”的多重身份场景。

## 3. 双层引导机制

### 3.1 首次进入系统

首次进入只介绍系统定位、任务层级、导航结构、当前身份和周次等总体框架，不深入讲解单个页面。

完成或跳过后不再自动弹出，处理状态按用户账号保存并跨设备生效。

### 3.2 首次主动进入板块

用户首次主动点击左侧栏板块时，展示该板块的专项引导。板块引导与系统框架引导分别记录，互不覆盖。

登录默认落地、刷新页面或通过飞书深链进入板块时不自动弹出专项引导，避免用户进入系统后连续受到两套引导打扰。

右上角保留“使用指南”入口，允许随时重看；手动重看不会重置原完成状态。

### 3.3 4.7.1 版本重看规则

4.7.1 将当前引导版本提升到 `2`。所有角色下一次进入系统都会重新看到一次对应指南；完成或跳过后，同一版本不再自动重复弹出。

4.7.2 更新部门负责人和任务负责人文案，但不提升引导版本。4.7.3 更新执行者和观察者文案，同样不提升引导版本。已完成 v2 的用户不会自动再次弹出；未完成 v2 或手动重看的用户会看到对应角色的新版指南。

### 3.4 前端维护位置

4.7.1 起，使用指南文案、页面匹配和 Tour 状态机维护在 `frontend/src/features/guides/`。`App.tsx` 只保留页面 refs、菜单调用、使用指南按钮和最终 Tour 渲染入口。

## 4. 4.7.1 总经办系统框架引导

总经办引导面向领导层，文案采用审阅和决策口径，避免使用系统配置、权限维护等技术表述。4.7.1 起，总经办指南跟随当前系统定位更新：工作台是进入系统后的行动入口，会议看板是会议审阅主入口。

### 第一步：公司任务推进与会议决策支持

说明系统用于统一呈现重点任务的责任分解、周度进展、风险与逾期情况，为经营会议审阅和决策提供依据。

### 第二步：任务体系与补充材料

说明战略目标、母任务、部门任务、子任务和周更新之间的关系，同时说明待归类事项和周报材料用于补充执行信息，不改变正式任务树统计。

### 第三步：工作台是行动入口

说明进入系统后先到工作台。工作台集中提供三类短路径入口：待归类事项、子任务执行周更新、拆解入口，便于用户快速进入本人需要处理的事项。

### 第四步：会议看板是审阅主入口

说明会议看板用于总经办会议和管理审阅，集中查看全局异常、风险逾期、未更新、部门差异和任务下钻明细。

### 第五步：确认身份与会议周期

提示核对当前登录人员、所属部门和系统周次，避免会议中混用不同周期的数据。

### 第六步：板块内专项说明

说明首次主动点击左侧板块时会出现专项引导，并提示右上角可随时重新查看。

## 5. 4.7.1 会议看板专项引导

### 第一步：会议看板用于审阅

说明会议看板不是日常填报入口，而是用于会议前准备和会议中审阅，重点看公司任务推进是否存在异常。

### 第二步：先看总览异常

引导先查看总览核心指标，识别未更新、风险、逾期和推进异常，再决定是否下钻到具体任务。

### 第三步：重点审阅风险与逾期

说明风险与逾期是会议优先审阅对象，需要核对来源任务、责任人、处理状态和截止日期。

### 第四步：判断本周更新完整度

说明本周更新情况和待更新人员用于判断数据是否完整，避免基于不充分信息做会议判断。

### 第五步：比较部门差异

说明部门横向对比用于识别推进压力集中、更新不稳定或风险较多的部门，再进入明细核对。

### 第六步：建议会议审阅顺序

建议按“总览异常、风险逾期、未更新、部门差异、下钻明细、会后跟进”的顺序使用。

## 6. 4.7.2 部门负责人系统框架引导

部门负责人引导强调“部门承接、推进质量和材料完整度”。它不把工作台写成明细页，而是明确工作台是入口，下方详细面板和业务页面承载完整信息。

### 第一步：部门承接、推进质量和材料完整度

说明部门负责人负责本部门任务承接和推进质量，同时关注部门任务补充、常态化事项和本周材料是否完整。

### 第二步：工作台先看行动入口

说明工作台首屏只保留待归类事项、子任务执行周更新和拆解入口；部门负责人完整信息在下方详细面板中查看。

### 第三步：查看范围以部门责任为边界

说明部门负责人可以查看本部门牵头母任务、本部门相关部门任务、本部门常态化记录和部门周报材料。

### 第四步：关注推进异常和材料补充

说明部门负责人重点看未更新、风险逾期、部门任务补充记录和本周材料统计，发现异常后再进入对应业务页处理。

### 第五步：区分管理责任和执行责任

说明部门负责人权限不自动包含子任务拆解或代填周更新。若本人同时是任务负责人或执行人，应按对应身份完成拆解或填报。

### 第六步：板块首次进入会继续提示

说明首次主动点击母任务管理、部门任务等板块时会出现专项说明；右上角可随时重新打开。

## 7. 4.7.2 部门负责人板块引导

### 7.1 母任务管理

1. 只展示本人部门牵头的母任务，用于从公司级事项查看本部门承接边界。
2. 先核对母任务负责人、牵头部门、截止日期和任务指标。
3. 通过任务卡进入详情，查看和维护该母任务下的部门任务承接关系。
4. 在母任务详情新增或维护部门任务，明确负责部门、任务负责人和截止日期。
5. 部门任务建立后，由任务负责人继续拆解到执行人；部门负责人重点检查责任是否清晰、节点是否合理。
6. 删除部门任务按归档隐藏处理，不物理删除历史；部门负责人不能仅凭该身份编辑母任务本身。

### 7.2 部门任务

1. 展示本人部门负责，或本人部门牵头母任务下的相关部门任务。
2. 优先核对负责部门、任务负责人、状态、待拆解数量、未更新和截止日期。
3. 展开部门任务后查看子任务执行人、本周完成内容、遗留事项、截止日期和补充记录。
4. 部门任务补充、本部门常态化和周报补充用于完善材料；正式进度仍来自任务树和周更新。
5. “拆解”按钮只在本人同时是该部门任务负责人时可用；部门负责人本身不代替任务负责人拆子任务。

### 7.3 子任务执行

仅当部门负责人本人存在有效子任务执行关系时出现。

1. 只有本人同时具备执行关系时，才需要填写周更新；管理查看和负责跟进都不等于代执行人填报。
2. 在“我执行”或“负责+执行”的子任务中点击“更新”，按执行人身份填写本周进展。
3. 未开启任务先点击“开启任务”；完成后再标记已完成。
4. 填写本周完成内容、下周计划和遗留事项。
5. 保存草稿不等于提交；只有“提交保存”才视为本周已提交。
6. 遗留事项不等于风险；确有影响和可能性的问题单独登记风险项。

## 9. 4.7.2 任务负责人系统框架引导

任务负责人引导聚焦“拆解、处理、跟进”。它明确任务负责人通过工作台拆解入口进入事项处理和部门任务拆解，但不替代执行人提交周更新。

### 第一步：把部门任务拆成可执行子任务

说明任务负责人负责本人名下部门任务的执行拆解，把任务落到具体执行人、截止日期和可跟踪的子任务上。

### 第二步：工作台先看拆解入口

说明工作台中的“拆解入口”用于快速查看待处理事项、可转子任务、负责部门任务和待拆子任务。

### 第三步：处理部门任务补充

说明员工挂载到部门任务的补充事项，可由任务负责人同意、退回、关闭；确实需要进入任务树时，再转为正式子任务。

### 第四步：拆解规则保持责任一致

说明创建子任务时明确执行人和截止日期；子任务负责人继承部门任务负责人，避免责任链分叉。

### 第五步：跟进执行但不代填

说明任务负责人需要关注执行人周更新、遗留事项、风险和完成状态；只有本人也是执行人时，才需要提交周更新。

### 第六步：板块首次进入会继续提示

说明首次主动点击部门任务或子任务执行板块时，会出现专项说明；右上角可随时重新打开。

## 10. 4.7.2 任务负责人板块引导

### 10.1 部门任务

1. 工作台会提示待处理事项、可转子任务和待拆任务；完整拆解仍回到部门任务页完成。
2. 优先查看任务负责人、状态、待拆解数量和截止日期，确认哪些任务还没有落到执行层。
3. 部门任务补充事项经判断需要纳入正式推进时，可转成子任务；否则可作为补充记录保留。
4. 点击“拆解”后填写具体任务、执行人和截止日期，子任务应足够具体，便于执行人按周提交进展。
5. 子任务负责人自动继承部门任务负责人，不在拆解窗口单独选择，避免部门任务责任和子任务责任分叉。
6. 展开部门任务后检查子任务执行人、本周进展、遗留事项、截止日期和风险状态，及时发现推进异常。

### 10.2 子任务执行

仅当任务负责人本人存在有效负责或执行子任务时出现。

1. 区分“我负责”“我执行”和“负责+执行”：“我负责”用于跟踪推进，“我执行”需要填写周更新。
2. 在“我负责”任务中，需要跟进执行人进展、遗留事项和风险，但不代替执行人填写周更新。
3. 只有“我执行”或“负责+执行”的子任务需要进入更新页，按执行人身份提交本周进展。
4. 保存草稿便于临时记录；只有点击“提交保存”，系统才认为本周更新已经正式提交。
5. 遗留事项用于记录距离完成还剩什么；确有影响和可能性的问题单独登记风险项。
6. 任务完成后周更新表单会锁定，后续主要通过历史记录查看提交内容。

## 11. 4.7.3 子任务执行者系统框架引导

子任务执行者引导聚焦“本人任务执行、周更新提交、待归类补充和周报材料”。它不讲任务拆解、负责人维护或会议审阅，避免把执行职责和管理职责混在一起。

### 第一步：推进本人子任务

说明子任务执行者负责推进本人名下的具体任务，并按周提交真实、可追溯的执行进展。

### 第二步：工作台先看周更新入口

说明工作台中的“子任务执行周更新”用于快速看到待更新、草稿、临近截止和风险入口；完整列表仍回到“子任务执行”页面。

### 第三步：先确认任务状态

说明任务可能处于待开启、进行中或已完成。待开启任务先开启再填报；已完成任务以查看为主，误点完成需要由子任务负责人或管理员撤回。

### 第四步：周更新要按周维护

说明本周完成、下周计划、遗留事项和附件共同构成本周记录。保存草稿便于临时记录，正式提交才代表本周更新完成。

### 第五步：补充事项进入待归类

说明不适合直接写进某个子任务的临时或日常工作，可通过“待归类事项”提交，再由责任人确认归类；周报中心会把正式任务和归类项分开展示。

### 第六步：风险和完成要分开处理

说明遗留事项不等于风险；确有影响和可能性的问题请单独登记风险。任务完成前请确认内容无误，完成后更新入口会锁定。

## 12. 4.7.3 子任务执行者板块引导

仅当执行者本人存在有效执行子任务时出现。

1. 区分“我执行”和“我负责”：“我执行”需要本人填报周更新；“我负责”是跟进责任，不代表可以代执行人填报。
2. 更新前核对任务编号、任务名称、所属部门任务、负责人、状态、本周提交状态和截止日期。
3. 点击“更新”进入本周填报页面；待开启任务进入后先点击“开启任务”，再填写进展。
4. 本周完成内容写已经推进的工作，下周计划写下一步安排，遗留事项写距离完成仍需处理的尾项；需要留存材料时可上传附件。
5. 保存草稿便于中途记录，但不代表本周已经提交；只有“提交保存”才算正式完成本周更新。
6. 发现真实风险时点击“风险”登记；标记完成后后续填报会锁定，误点完成或审批后需要继续推进时，由子任务负责人或管理员撤回为进行中。

## 13. 4.7.3 观察者系统框架引导

观察者引导聚焦“只读审阅、任务追溯和人事周报材料导出”。它不把观察者写成管理者或填报人，但会提示多重身份用户仍需按任务负责人或执行人身份处理本人任务。

### 第一步：只读审阅与材料导出

说明观察者用于公司级任务推进的只读审阅、过程追溯和人事周报材料导出，重点关注任务推进质量、风险、逾期和历史证据。

### 第二步：工作台按身份展示入口

说明工作台会按本人角色叠加展示入口。观察者可看到月度周报 Excel 导出；如果本人兼任执行人或负责人，也会看到对应处理入口。

### 第三步：会议看板用于全局审阅

说明会议看板用于查看总览异常、风险逾期、未更新、部门差异和任务下钻明细，是管理审阅的主入口。

### 第四步：沿任务层级追溯过程

说明任务从母任务、部门任务到子任务逐级拆解。观察者可沿层级下钻，并通过历史时间线查看周更新、附件和处理痕迹。

### 第五步：月度导出服务人事材料

说明观察者可在工作台按月份导出 Excel。系统优先使用已确认周报，未确认周次会使用实时草稿并标记为未确认。

### 第六步：保持只读边界和多身份边界

说明观察者身份不新增、拆分、编辑或代填任务；如果同时也是任务负责人或执行人，对应事项按该身份处理。

## 14. 4.7.3 观察者板块引导

### 14.1 会议看板

1. 先看总览异常，判断总体推进是否健康。
2. 风险、逾期和高风险事项优先下钻，核对来源任务、责任人、处理状态和截止日期。
3. 关注本周更新完整度和待更新人员，避免基于不完整信息审阅。
4. 结合部门横向对比，识别推进压力集中、更新不稳定或风险较多的部门。
5. 从总览进入母任务、部门任务、子任务和历史时间线，查看周更新、附件、风险和处理痕迹。
6. 建议按“总览异常、风险逾期、未更新、部门差异、下钻明细、会后跟进”的顺序审阅。

### 14.2 母任务管理

1. 只读查看公司级母任务、牵头部门、负责人、截止日期和当前状态。
2. 通过任务卡进入详情，查看该母任务下的部门任务拆解、子任务推进、周更新和补充材料脉络。
3. 重点关注牵头部门、任务负责人、负责部门、执行人和截止日期是否清晰。
4. 观察者不在这里新增、拆分或编辑任务；如本人另有部门负责人职责，应按对应身份进入相应入口处理。

### 14.3 部门任务

1. 查看各部门承接、任务负责人、截止日期、状态、子任务拆解和补充记录。
2. 展开部门任务后查看子任务执行人、本周进展、遗留事项、风险、附件和截止节点。
3. 如果本人也是某个部门任务的任务负责人，需要额外关注待拆解、待处理补充事项、执行人更新和风险处理。
4. 观察者身份只做审阅和追溯，不代替负责人新增子任务、调整执行人、确认事项或填写周更新。

### 14.4 历史时间线

1. 按任务层级和周次查看完成内容、遗留事项、附件、风险和历史提交。
2. 同一任务可横向比较不同周次更新，判断问题是偶发、连续、改善还是停滞。
3. 从母任务到部门任务再到子任务逐层展开，定位进展、附件和遗留事项来自哪个责任层级。
4. 时间线用于审阅、复盘和过程追溯，不在这里直接修改历史提交或代替业务处理。

### 14.5 子任务执行

仅当观察者本人存在有效子任务执行关系时出现。

1. 观察者身份本身不承担填报责任；该板块出现说明本人当前也有需要执行和更新的子任务。
2. 属于本人执行的子任务，需要进入更新页填写本周完成内容、下周计划、遗留事项，并按需要上传附件。
3. 保存草稿只用于临时记录；只有正式提交后，系统才认为本周更新完成。
4. 遗留事项用于说明剩余工作；影响和可能性明确的问题，应单独登记风险项。这里的填报责任来自执行人身份，而不是观察者身份。

## 15. 建议审核事项

1. 五类角色是否符合当前组织管理口径。
2. 总经办引导是否保持领导层审阅与决策视角。
3. 观察者引导是否准确体现只读审阅、任务追溯和多重身份边界。
4. 部门负责人引导是否准确区分管理责任、任务负责人责任和执行人责任。
5. 任务负责人引导是否准确区分拆解责任、跟踪责任和执行人周更新责任。
6. 子任务执行者引导是否准确聚焦本人执行、填报、风险和完成闭环。
7. 板块引导只由首次主动点击触发是否符合使用习惯。
