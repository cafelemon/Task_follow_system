# 任务跟踪系统角色化使用引导审核说明

## 1. 审核目的

本文档说明 `2.3.4` 起的角色化引导框架，供管理层审核角色口径、引导层级和已完成角色的引导内容。

使用引导不替代制度培训。它只负责帮助用户理解系统框架、找到与职责相关的入口，并在首次使用具体板块时掌握基本审阅或操作方法。

## 2. 五类引导身份

| 引导身份 | 主要适用人员 | 核心职责 |
| --- | --- | --- |
| 总经办会议相关 | 总经理、总经办秘书 | 审阅公司任务推进、风险、逾期和会议决策事项 |
| 部门负责人 | 具有部门负责人角色且已配置所属部门的人员 | 查看本部门牵头母任务，拆分和管理相关部门任务 |
| 任务负责人 | 部门任务负责人 | 拆分子任务、指定执行人、跟踪进展和风险 |
| 子任务执行者 | 子任务执行人 | 执行任务、提交周更新、登记发现的风险 |
| 观察者 | 获得观察角色的人员 | 全局只读审阅、任务追溯和会议准备 |

多身份用户只展示一套主引导，优先级为：

`总经办会议相关 > 观察者 > 部门负责人 > 任务负责人 > 子任务执行者`

系统管理员和信息中心维护身份不再单独形成业务引导。若技术管理员同时拥有业务角色，则按业务角色展示。观察者优先于任务负责人和执行者，是为了覆盖“以审阅为主、同时兼任具体任务”的多重身份场景。

## 3. 双层引导机制

### 3.1 首次进入系统

首次进入只介绍系统定位、任务层级、导航结构、当前身份和周次等总体框架，不深入讲解单个页面。

完成或跳过后不再自动弹出，处理状态按用户账号保存并跨设备生效。

### 3.2 首次主动进入板块

用户首次主动点击左侧栏板块时，展示该板块的专项引导。板块引导与系统框架引导分别记录，互不覆盖。

登录默认落地、刷新页面或通过飞书深链进入板块时不自动弹出专项引导，避免用户进入系统后连续受到两套引导打扰。

右上角保留“使用指南”入口，允许随时重看；手动重看不会重置原完成状态。

## 4. 2.3.4 总经办系统框架引导

总经办引导面向领导层，文案采用审阅和决策口径，避免使用系统配置、权限维护等技术表述。

### 第一步：公司任务推进与会议决策支持

说明系统用于统一呈现重点任务的责任分解、周度进展、风险与逾期情况，为经营会议审阅和决策提供依据。

### 第二步：四级任务框架

说明战略目标、母任务、部门任务和子任务之间的关系，帮助使用者理解看板指标最终来自哪些执行数据。

### 第三步：以会议看板为主要入口

说明会议看板承担集中审阅功能；战略目标、母任务、部门任务和历史时间线用于进一步追溯任务来源与执行过程。

### 第四步：确认身份与会议周期

提示核对当前登录人员、所属部门和系统周次，避免会议中混用不同周期的数据。

### 第五步：板块内专项说明

说明首次主动点击左侧板块时会出现专项引导，并提示右上角可随时重新查看。

## 5. 2.3.4 会议看板专项引导

### 第一步：三种会议视角

介绍总览、母任务看板和部门看板。总览用于识别异常，母任务看板用于审阅公司级事项，部门看板用于横向比较部门推进情况。

### 第二步：六项核心指标

引导优先关注本周待更新、风险任务和逾期任务，并说明指标可以点击下钻到具体任务和责任人。

### 第三步：本周信息完整度

说明本周更新状态和近周提交趋势的用途，用于判断填报完整度及执行节奏是否稳定。

### 第四步：风险与逾期审阅

说明如何核对风险等级、处理责任人和截止日期，以及具备权限时如何进入风险处置。

### 第五步：节点和部门差异

说明母任务截止日期用于识别临近节点，部门看板用于比较任务量、待更新、风险和逾期分布。

### 第六步：建议会议顺序

建议按“总览识别异常、下钻任务明细、确认责任人与处理要求、形成会后跟进事项”的顺序使用。

## 6. 2.3.5 部门负责人系统框架引导

部门负责人引导兼顾管理闭环和具体操作。它强调部门负责人负责把公司级任务承接到部门级任务，并持续跟进责任人、节点、进展和风险，但不把子任务拆解或周更新误写成部门负责人本身的权限。

### 第一步：部门任务承接与责任落地

说明部门负责人负责承接本部门牵头的公司任务，并把任务拆分到清晰的负责部门、任务负责人和截止节点。

### 第二步：查看范围以部门责任为边界

说明部门负责人可以查看本部门牵头母任务，以及与本人部门相关的部门任务；普通同部门人员不会自动获得这些视图。

### 第三步：核心流程从母任务详情开始

说明进入母任务详情后，通过“新增”建立部门任务，明确负责部门、任务负责人和截止日期，再由任务负责人继续拆解子任务。

### 第四步：跟进部门任务闭环

说明部门任务页用于检查任务状态、子任务进展、本周更新、遗留事项、风险和截止节点，便于及时推动责任人处理。

### 第五步：区分管理责任和执行责任

说明部门负责人权限不自动包含子任务拆解或周更新。若本人同时是任务负责人或执行人，应按对应身份完成拆解或填报。

### 第六步：板块首次进入会继续提示

说明首次主动点击母任务管理、部门任务等板块时会出现专项说明；右上角可随时重新打开。

## 7. 2.3.5 部门负责人板块引导

### 7.1 母任务管理

1. 只展示本人部门牵头的母任务。
2. 先核对母任务负责人、牵头部门、截止日期和任务指标。
3. 通过任务卡进入详情，查看已拆分的部门任务和子任务。
4. 在母任务详情点击“新增”，填写部门任务内容、负责部门、任务负责人和截止日期。
5. 部门任务建立后，由任务负责人继续拆解子任务，部门负责人重点检查责任是否清晰、节点是否合理。
6. 删除部门任务按归档隐藏处理，不物理删除历史；部门负责人不能仅凭该身份编辑母任务本身。

### 7.2 部门任务

1. 展示本人部门负责，或本人部门牵头母任务下的相关部门任务。
2. 优先核对负责部门、任务负责人、状态和待拆解数量。
3. 展开部门任务后查看子任务执行人、本周完成内容、遗留事项和截止日期。
4. 如发现责任人、负责部门或截止日期不合理，回到母任务详情维护部门任务。
5. “拆解”按钮只在本人同时是该部门任务负责人时可用；部门负责人本身不代替任务负责人拆子任务。

### 7.3 子任务执行

仅当部门负责人本人存在有效子任务执行关系时出现。

1. 区分“我执行”“我负责”和“管理查看”：只有执行关系可以填写周更新。
2. 从“我执行”或“负责+执行”的子任务点击“更新”进入填报页。
3. 未开启任务先点击“开启任务”；完成后再标记已完成。
4. 填写本周完成内容、下周计划和遗留事项。
5. 保存草稿不等于提交；只有“提交保存”才视为本周已提交。
6. 遗留事项不等于风险；确有影响和可能性的问题单独登记风险项。

## 8. 后续版本安排

- `2.3.4`：总经办会议相关。
- `2.3.5`：部门负责人。
- `2.3.6`：任务负责人。
- `2.3.7`：子任务执行者。
- `2.3.8`：观察者。

至 `2.3.8`，五类业务身份的双层引导已经补齐。后续版本可继续按真实使用反馈优化单个角色文案或板块锚点。

## 9. 2.3.6 任务负责人系统框架引导

任务负责人引导聚焦“把部门任务拆成可执行子任务，并持续跟踪执行闭环”。它明确任务负责人不进入母任务拆分职责，也不替代执行人提交周更新。

### 第一步：承接部门任务并拆解执行

说明任务负责人负责承接本人名下的部门任务，并把任务拆解成可执行、可跟踪、可按周更新的子任务。

### 第二步：只处理自己负责的部门任务

说明任务负责人不承担母任务拆分职责，也不会因为任务负责人身份进入母任务管理；主入口是部门任务。

### 第三步：从部门任务进入拆解

说明在部门任务页找到本人负责的任务，点击“拆解”创建子任务，明确具体任务、执行人和截止日期。

### 第四步：持续跟踪执行闭环

说明拆解后需要关注待拆解数量、执行人周更新、遗留事项、风险和完成状态，确保任务进入真实推进。

### 第五步：兼任执行人时要提交更新

说明如果本人同时是某个子任务的执行人，需要按执行人身份进入子任务执行页填写并提交本周进展。

### 第六步：板块首次进入会继续提示

说明首次主动点击部门任务或子任务执行板块时，会出现专项说明；右上角可随时重新打开。

## 10. 2.3.6 任务负责人板块引导

### 10.1 部门任务

1. 部门任务页是任务负责人日常工作的主入口，用于查看本人负责的部门任务及其拆解情况。
2. 优先查看任务负责人、状态、待拆解数量和截止日期，确认哪些任务还没有落到具体执行人。
3. 点击“拆解”后填写具体任务、执行人和截止日期，子任务应足够具体，便于执行人按周提交进展。
4. 子任务负责人自动继承部门任务负责人，不在拆解窗口单独选择，避免部门任务责任和子任务责任分叉。
5. 展开部门任务后检查子任务执行人、本周进展、遗留事项和截止日期，及时发现未更新或推进异常。
6. 编辑子任务时只维护任务内容、执行人和截止日期；部门任务负责人变化会自动同步到子任务负责人。

### 10.2 子任务执行

仅当任务负责人本人存在有效负责或执行子任务时出现。

1. 区分“我负责”“我执行”和“负责+执行”：“我负责”用于跟踪推进，“我执行”需要填写周更新。
2. 在“我负责”任务中，需要跟进执行人进展和风险，但不代替执行人填写周更新。
3. 在“我执行”或“负责+执行”的子任务中点击“更新”，进入本周填报页面。
4. 保存草稿便于临时记录；只有点击“提交保存”，系统才认为本周更新已经正式提交。
5. 遗留事项用于记录距离完成还剩什么；确有影响和可能性的问题单独登记风险项。
6. 任务完成后周更新表单会锁定，后续主要通过历史记录查看提交内容。

## 11. 2.3.7 子任务执行者系统框架引导

子任务执行者引导聚焦“本人任务执行和周更新提交”。它不讲任务拆解、负责人维护或会议审阅，避免把执行职责和管理职责混在一起。

### 第一步：按计划推进本人子任务

说明子任务执行者负责推进本人名下的具体任务，并按周提交真实、可追溯的执行进展。

### 第二步：主要入口是子任务执行

说明执行者主要从“子任务执行”进入本人任务，不承担母任务拆分或部门任务拆解职责。

### 第三步：先确认任务状态

说明任务可能处于待开启、进行中或已完成。待开启任务需要先开启，再填写本周进展。

### 第四步：周更新要按周维护

说明本周完成内容、下周计划和遗留事项分别记录已完成工作、下一步安排和距离完全完成仍需处理的事项。

### 第五步：风险需要单独登记

说明遗留事项不等于风险；确有影响和可能性的问题，应使用风险入口单独登记。

### 第六步：正式提交影响提醒

说明周五提醒以正式提交为准。保存草稿便于临时记录，但不会视为本周已提交。

## 12. 2.3.7 子任务执行者板块引导

仅当执行者本人存在有效执行子任务时出现。

1. “我执行”展示本人需要推进和更新的子任务，是执行人最常用的工作区。
2. 更新前核对任务编号、任务名称、所属部门任务、负责人、状态和截止日期。
3. 点击“更新”进入本周填报页面；待开启任务进入后先点击“开启任务”，再填写进展。
4. 本周完成内容写已经推进的工作，下周计划写下一步安排，遗留事项写距离完成仍需处理的尾项。
5. 保存草稿不会停止周提醒；只有“提交保存”才代表本周更新正式完成。
6. 发现真实风险时点击“风险”登记；任务完成后标记完成，后续更新入口会锁定。

## 13. 2.3.8 观察者系统框架引导

观察者引导聚焦“全局只读审阅和任务追溯”。它不把观察者写成管理者或填报人，但会提示多重身份用户仍需按任务负责人或执行人身份处理本人任务。

### 第一步：全局只读审阅与任务追溯

说明观察者用于公司级任务推进的只读审阅，重点关注任务推进质量、风险、逾期和历史过程。

### 第二步：会议看板看全局

说明会议看板是主要审阅入口，用于快速查看核心指标、风险逾期、更新完整度和部门差异。

### 第三步：按任务层级理解责任拆解

说明任务从母任务、部门任务到子任务逐级拆解。观察者可沿层级下钻，查看责任边界和执行进展。

### 第四步：保持只读边界

说明观察者不负责新增、拆分、编辑或代填任务，主要用于审阅、追溯和会前准备。

### 第五步：多重身份分开处理

说明如果本人同时也是任务负责人或执行人，对应任务仍按该身份跟进；观察者身份本身不增加写入职责。

### 第六步：板块首次进入会继续提示

说明首次主动点击左侧板块时会补充该板块的审阅方法；右上角可随时重新打开当前页面指南。

## 14. 2.3.8 观察者板块引导

### 14.1 会议看板

1. 先看核心指标，判断总体推进是否健康。
2. 通过总览、母任务看板和部门看板切换不同审阅口径。
3. 关注本周更新完整度和待更新人员，避免基于不完整信息讨论。
4. 风险、逾期和高风险事项优先下钻，查看来源任务、责任人和处理状态。
5. 结合趋势和部门横向对比，识别连续未更新、推进滞后或压力集中的方向。
6. 建议按“总览异常、下钻明细、确认责任人、形成会后跟进”的顺序审阅。

### 14.2 母任务管理

1. 只读查看公司级母任务、牵头部门、负责人、截止日期和当前状态。
2. 通过任务卡进入详情，查看该母任务下的部门任务拆解、子任务推进和周更新脉络。
3. 重点关注牵头部门、任务负责人、负责部门和截止日期是否清晰。
4. 观察者不在这里新增、拆分或编辑任务；如本人另有部门负责人职责，应按对应身份处理。

### 14.3 部门任务

1. 查看各部门承接、任务负责人、截止日期、状态和待拆解情况。
2. 展开部门任务后查看子任务执行人、本周进展、遗留事项、风险和截止节点。
3. 如果本人也是某个部门任务的任务负责人，需要额外关注待拆解、执行人更新和风险处理。
4. 观察者身份只做审阅和追溯，不代替负责人新增子任务、调整执行人或填写周更新。

### 14.4 历史时间线

1. 按任务层级和周次查看完成内容、遗留事项、附件和历史提交。
2. 同一任务可横向比较不同周次更新，判断问题是偶发、连续还是已经改善。
3. 从母任务到部门任务再到子任务逐层展开，定位进展内容来自哪个责任层级。
4. 时间线用于会前准备、会后复盘和过程追溯，不在这里直接修改历史提交。

### 14.5 子任务执行

仅当观察者本人存在有效子任务执行关系时出现。

1. 观察者身份本身不承担填报责任；该板块出现说明本人当前也有需要执行和更新的子任务。
2. 属于本人执行的子任务，需要进入更新页填写本周完成内容、下周计划和遗留事项。
3. 保存草稿只用于临时记录；只有正式提交后，系统才认为本周更新完成。
4. 遗留事项用于说明剩余工作；影响和可能性明确的问题，应单独登记风险项。

## 15. 建议审核事项
