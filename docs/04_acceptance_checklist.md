# 公司工作任务跟踪系统验收测试清单

## 1. 文档用途

本文档用于记录公司工作任务跟踪系统的验收测试清单。每个阶段开发完成后，应按本文档逐项验证，并把结果记录到 `06_progress.md`。

## 2. 文档与项目准备

- [ ] `docs/00_overview.md` 到 `docs/07_decisions.md` 均存在。
- [ ] 文档文件名全部为小写编号格式。
- [ ] 产品需求、架构、验收、进度、决策文档内容互相一致。
- [ ] MVP 范围和非 MVP 范围已经明确。
- [ ] 根目录 `VERSION`、后端版本、前端 `package.json` 版本均为 `1.0.0`。
- [ ] `backend/`、`frontend/`、`deploy/`、`README.md` 均存在。
- [ ] 已确认部署服务器、数据库、NAS、反向代理和飞书应用准备事项。

## 3. 身份、部门和权限

- [ ] 用户可通过飞书 open_id 或系统账号识别。
- [ ] 用户姓名、部门、角色、状态可维护。
- [ ] 系统管理员可维护角色和权限。
- [ ] 普通执行人只能看到自己有权限的任务和子任务。
- [ ] 任务负责人可以查看和拆分自己负责的任务。
- [ ] 部门负责人可以查看本部门任务汇总。
- [ ] 管理层或总经办可查看全局看板和会议视图。
- [ ] 无权限用户无法直接通过链接访问受限任务详情。

## 4. 任务创建

- [ ] 总经办或秘书可以创建战略目标、母任务或部门任务。
- [ ] 创建任务时必填字段缺失会被提交前拦截。
- [ ] 负责人、部门和时间范围必须合法。
- [ ] 任务编号由系统生成，用户不能手填关键编号。
- [ ] 创建成功后生成任务事件。
- [ ] 创建成功后相关负责人可以在“我的任务”中看到任务。

## 5. 任务拆分

- [ ] 任务负责人可以进入任务拆分页。
- [ ] 任务负责人可以创建一个或多个子任务。
- [ ] 子任务执行人从用户列表中选择。
- [ ] 子任务计划时间必须在合法范围内。
- [ ] 子任务编号由系统自动生成。
- [ ] 校验通过后才保存子任务。
- [ ] 子任务保存后生成对应任务事件。
- [ ] 子任务保存后执行人可以在“本周填报”中看到待更新项。

## 6. 每周更新

- [ ] 执行人只能看到自己需要更新的子任务。
- [ ] 填报页显示当前周周期和截止时间。
- [ ] 支持填写本周完成、下周计划、风险问题和附件。
- [ ] 必填内容缺失时不能提交。
- [ ] 支持保存草稿。
- [ ] 支持提交本周更新。
- [ ] 提交后生成独立周更新记录。
- [ ] 提交后任务详情时间线可看到该周更新。
- [ ] 过去周更新默认不会被本周填报覆盖。

## 7. 任务详情和时间线

- [ ] 有权限用户可以打开任务详情。
- [ ] 任务详情展示任务基本信息、负责人、部门、时间、状态。
- [ ] 任务详情展示子任务列表、执行人、状态和本周更新情况。
- [ ] 时间线按时间展示创建、拆分、更新、延期、变更、完成等事件。
- [ ] 可以按全部历史、本周、风险、附件等视角查看。
- [ ] 风险区集中展示未解决风险和需要协调的问题。
- [ ] 附件可以在权限范围内查看或下载。

## 8. 管理看板和会议视图

- [ ] 管理看板展示任务总数、进行中、已完成、延期、有风险、未更新。
- [ ] 支持按部门、负责人、状态、时间筛选。
- [ ] 点击指标可以下钻到任务列表。
- [ ] 点击任务可以进入任务详情时间线。
- [ ] 会议视图展示本周重点任务、本周新增风险、延期和未更新任务、已完成任务、需要会议决策的问题。
- [ ] 会议视图支持按部门切换。
- [ ] 会议视图支持生成会议版本或导出。

## 9. 飞书机器人和提醒

- [ ] 执行人可以收到本周任务更新卡片。
- [ ] 任务负责人可以收到任务拆分与跟进卡片。
- [ ] 管理层可以收到本周任务看板卡片。
- [ ] 信息中心可以收到任务系统运行状态卡片。
- [ ] 飞书卡片按钮可以跳转到对应 Web 页面。
- [ ] 定时提醒可以按配置触发。
- [ ] 逾期和未更新提醒可以按规则触发。
- [ ] 通知记录保存发送状态、目标用户、卡片类型和处理结果。

## 10. 附件、导出和历史迁移

- [ ] 周更新支持上传附件。
- [ ] 附件文件保存到 NAS 或指定文件存储位置。
- [ ] 数据库保存附件元数据和关联关系。
- [ ] 无权限用户不能下载受限附件。
- [ ] 支持按任务、按周、按部门导出。
- [ ] 支持导出会议版本或归档快照。
- [ ] 历史 Base 或快照导入前会进行字段映射和校验。

## 11. 部署和访问

- [ ] 系统可在目标服务器启动。
- [ ] 数据库迁移可重复执行。
- [ ] Web 页面可通过反向代理访问。
- [ ] HTTPS 和访问控制配置生效。
- [ ] 内部网络和出差外部访问使用同一套身份与权限逻辑。
- [ ] 后台任务可以稳定运行。
- [ ] 日志能记录关键业务操作、错误和通知结果。
- [ ] 备份策略覆盖数据库和附件元数据。

## 12. 页面体验

- [ ] 页面视觉正式、清爽、稳定，不呈现临时工具感。
- [ ] 用户进入系统后能快速找到自己要处理的事项。
- [ ] 管理层能在看板和会议视图中快速看到重点信息。
- [ ] 执行人可以在短路径内完成本周填报。
- [ ] 负责人可以清楚看到拆分进度和未更新人员。
- [ ] 页面按身份显示操作，不展示用户无权操作的按钮。
- [ ] 错误提示发生在提交前。
- [ ] 窄屏或笔记本访问不影响核心流程使用。
