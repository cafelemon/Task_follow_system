# 公司工作任务跟踪系统版本规划

## 1. 文档用途

本文档用于记录公司工作任务跟踪系统的阶段规划、版本边界和优先级。每个阶段的具体实现应在进入开发前拆分为更细任务。

## 2. 规划原则

- 先保证任务跟踪主链路闭环，再做周报、日报、绩效等扩展集成。
- 先建设系统自己的数据模型、权限和历史记录，不把 Base 当作主业务系统。
- 先完成 Web 主操作入口，再逐步增强飞书卡片交互。
- 先满足管理层、负责人、执行人三个核心场景，再扩展更多统计和自动化。
- 每个版本都要有可验证的验收清单，不以“页面能打开”作为完成标准。

## 3. V0 文档和原型阶段

目标：把方向、边界、核心流程和验收口径定清楚，为开发做准备。

主要事项：

- 完成项目总览、产品需求、版本规划、架构、验收清单、AI 开发协议、进度和决策文档。
- 梳理现有 Base 字段、视图、自动化和周留存流程。
- 明确 MVP 数据对象、角色、权限关系和关键状态。
- 产出核心页面低保真或高保真草稿。
- 确认部署服务器、反向代理、NAS 附件路径和飞书应用准备情况。

交付标准：

- `docs/` 中 00 到 07 文档齐备。
- 核心版本范围和暂缓范围清晰。
- 关键业务口径已经记录在决策文档中。

## 4. V1 MVP 核心闭环

目标：完成任务创建、拆分、每周更新、时间线、权限和管理看板的基础可用版本。

版本号：`1.0.0`。

主要事项：

- 建立 FastAPI 后端服务、SQLAlchemy 数据库模型、Alembic 迁移机制和基础配置。
- 实现用户、部门、角色、权限矩阵的基础管理。
- 实现战略目标、母任务、部门任务、子任务、周更新、任务事件、通知记录等核心模型。
- 实现任务创建、任务拆分、周更新提交、任务详情时间线。
- 实现工作台、战略目标、母任务管理、部门任务、子任务执行、每周更新、会议看板、风险与逾期、历史时间线、通知记录、人员、角色权限、任务详情页面。
- 实现编号自动生成、人员选择、时间范围和必填字段校验。
- 实现自动会议看板和基础会议材料导出能力。
- 飞书 1.0.0 只做 open_id、模拟通知和卡片跳转预留，不接真实发送。
- 部署 1.0.0 采用本地优先 Docker Compose，附件默认本地目录，预留 NAS 配置。

交付标准：

- 执行人可以完成每周填报。
- 负责人可以拆分任务并查看执行人更新情况。
- 管理层可以查看整体状态、风险、延期和未更新情况。
- 任意任务可以查看历史进展。
- 权限控制能阻止无权限查看和编辑。

## 5. V1.1 飞书提醒和会议视图增强

目标：增强飞书入口和会议场景，让系统更贴近日常工作节奏。

主要事项：

- 接入企业自建应用机器人。
- 按用户身份推送执行人、任务负责人、管理层、信息中心卡片。
- 实现定时提醒、逾期提醒、未更新提醒和推送记录。
- 完善会议视图，集中展示本周重点任务、风险、延期、未更新、已完成和待决策事项。
- 支持生成会议版本或按周导出。
- 增加机器人推送失败、用户点击、处理结果等可观测记录。

交付标准：

- 用户可以从飞书卡片进入对应 Web 页面。
- 每周提醒能按身份准确发送。
- 管理层会议可以直接使用会议视图浏览重点信息。
- 信息中心可以查看推送和异常记录。

## 6. V1.2 页面层级和权限修订

目标：修正战略目标、母任务、部门任务三个页面的查看层级，让 Web 入口更贴近真实任务结构。

版本号：`1.2.0`。

主要事项：

- 顶部导航精简为姓名、部门、日期所属周和退出，移除快捷操作按钮和角色标签。
- 战略目标页四目标均匀展示，支持进入目标详情查看关联母任务。
- 母任务管理页增加页内目录，母任务详情展示部门级任务，不直接跳到子任务级别。
- 母任务管理入口限制为系统管理员、总经理、总经办秘书、观察者和母任务负责人。
- 部门任务页取消母任务卡片，直接展示部门级任务树状总览。

交付标准：

- 用户能按战略目标到母任务、母任务到部门级任务逐层钻取。
- 普通部门成员只能看到自己部门关联的部门级任务。
- 管理员和总经理可以通过部门侧栏查看不同部门任务。

## 7. V1.3 交互和周更新合并

目标：降低任务页面的误导性指标，把每周更新并入子任务执行，强化母任务管理操作。

版本号：`1.3.0`。

主要事项：

- 返回按钮统一放到页面标题左上方。
- 母任务管理目录点击直接进入母任务详情，新增母任务新增、编辑和归档入口。
- 全站移除进度条展示，不再用百分比表达任务推进。
- 每周更新入口并入子任务执行，子任务行内提供更新按钮。
- 周更新支持失焦自动保存草稿、提交保存和离开提醒。

交付标准：

- 母任务可按权限新增、编辑和归档隐藏。
- 子任务更新页可恢复草稿，提交后进入会议看板和历史链路。
- 旧每周更新菜单不再显示，旧路由跳转到子任务执行。

## 8. V2 历史迁移、统计导出和更多系统集成

目标：把过渡期数据迁移进新系统，并逐步接入更多管理场景。

主要事项：

- 从现有 Base 或历史快照导入任务、子任务、周更新和附件索引。
- 建立历史数据清洗、字段映射和导入校验流程。
- 增强部门统计、填报率、逾期率、风险趋势和任务完成分析。
- 按需与日报、周报、飞书任务中心或其他系统做单向或双向集成。
- 完善备份、恢复、归档、审计日志和长期运维能力。
- 根据真实使用反馈优化页面效率和权限矩阵。

交付标准：

- 关键历史数据可在新系统中查询。
- 管理层可以查看跨周、跨部门、跨负责人趋势。
- 导出数据可以满足会议、归档和管理复盘需要。
- 系统具备长期运维所需的备份、审计和异常处理能力。

## 7. 暂缓事项

以下事项不进入 V1，待核心模型稳定后再评估：

- 自动生成并提交正式周报。
- 自动同步日报系统。
- 飞书任务中心深度双向同步。
- 复杂绩效考核和组织评分规则。
- 面向外部客户或跨公司协作的权限模型。
