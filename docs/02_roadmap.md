# 公司工作任务跟踪系统版本规划

## 1. 文档用途

本文档用于记录公司工作任务跟踪系统的阶段规划、版本边界和优先级。每个阶段的具体实现应在进入开发前拆分为更细任务。

## 2. 规划原则

- 先保证任务跟踪主链路闭环，再做周报、日报、绩效等扩展集成。
- 先建设系统自己的数据模型、权限和历史记录，不把 Base 当作主业务系统。
- 先完成 Web 主操作入口，再逐步增强飞书卡片交互。
- 先满足管理层、负责人、执行人三个核心场景，再扩展更多统计和自动化。
- 每个版本都要有可验证的验收清单，不以“页面能打开”作为完成标准。

## 3. V0 文档和原型阶段

目标：把方向、边界、核心流程和验收口径定清楚，为开发做准备。

主要事项：

- 完成项目总览、产品需求、版本规划、架构、验收清单、AI 开发协议、进度和决策文档。
- 梳理现有 Base 字段、视图、自动化和周留存流程。
- 明确 MVP 数据对象、角色、权限关系和关键状态。
- 产出核心页面低保真或高保真草稿。
- 确认部署服务器、反向代理、NAS 附件路径和飞书应用准备情况。

交付标准：

- `docs/` 中 00 到 07 文档齐备。
- 核心版本范围和暂缓范围清晰。
- 关键业务口径已经记录在决策文档中。

## 4. V1 MVP 核心闭环

目标：完成任务创建、拆分、每周更新、时间线、权限和管理看板的基础可用版本。

版本号：`1.0.0`。

主要事项：

- 建立 FastAPI 后端服务、SQLAlchemy 数据库模型、Alembic 迁移机制和基础配置。
- 实现用户、部门、角色、权限矩阵的基础管理。
- 实现战略目标、母任务、部门任务、子任务、周更新、任务事件、通知记录等核心模型。
- 实现任务创建、任务拆分、周更新提交、任务详情时间线。
- 实现工作台、战略目标、母任务管理、部门任务、子任务执行、每周更新、会议看板、风险与逾期、历史时间线、通知记录、人员、角色权限、任务详情页面。
- 实现编号自动生成、人员选择、时间范围和必填字段校验。
- 实现自动会议看板和基础会议材料导出能力。
- 飞书 1.0.0 只做 open_id、模拟通知和卡片跳转预留，不接真实发送。
- 部署 1.0.0 采用本地优先 Docker Compose，附件默认本地目录，预留 NAS 配置。

交付标准：

- 执行人可以完成每周填报。
- 负责人可以拆分任务并查看执行人更新情况。
- 管理层可以查看整体状态、风险、延期和未更新情况。
- 任意任务可以查看历史进展。
- 权限控制能阻止无权限查看和编辑。

## 5. V1.1 飞书提醒和会议视图增强

目标：增强飞书入口和会议场景，让系统更贴近日常工作节奏。

主要事项：

- 接入企业自建应用机器人。
- 按用户身份推送执行人、任务负责人、管理层、信息中心卡片。
- 实现定时提醒、逾期提醒、未更新提醒和推送记录。
- 完善会议视图，集中展示本周重点任务、风险、延期、未更新、已完成和待决策事项。
- 支持生成会议版本或按周导出。
- 增加机器人推送失败、用户点击、处理结果等可观测记录。

交付标准：

- 用户可以从飞书卡片进入对应 Web 页面。
- 每周提醒能按身份准确发送。
- 管理层会议可以直接使用会议视图浏览重点信息。
- 信息中心可以查看推送和异常记录。

## 6. V1.2 页面层级和权限修订

目标：修正战略目标、母任务、部门任务三个页面的查看层级，让 Web 入口更贴近真实任务结构。

版本号：`1.2.0`。

主要事项：

- 顶部导航精简为姓名、部门、日期所属周和退出，移除快捷操作按钮和角色标签。
- 战略目标页四目标均匀展示，支持进入目标详情查看关联母任务。
- 母任务管理页增加页内目录，母任务详情展示部门级任务，不直接跳到子任务级别。
- 母任务管理入口限制为系统管理员、总经理、总经办秘书、观察者和母任务负责人。
- 部门任务页取消母任务卡片，直接展示部门级任务树状总览。

交付标准：

- 用户能按战略目标到母任务、母任务到部门级任务逐层钻取。
- 普通部门成员只能看到自己部门关联的部门级任务。
- 管理员和总经理可以通过部门侧栏查看不同部门任务。

## 7. V1.3 交互和周更新合并

目标：降低任务页面的误导性指标，把每周更新并入子任务执行，强化母任务管理操作。

版本号：`1.3.0`。

主要事项：

- 返回按钮统一放到页面标题左上方。
- 母任务管理目录点击直接进入母任务详情，新增母任务新增、编辑和归档入口。
- 全站移除进度条展示，不再用百分比表达任务推进。
- 每周更新入口并入子任务执行，子任务行内提供更新按钮。
- 周更新支持失焦自动保存草稿、提交保存和离开提醒。

交付标准：

- 母任务可按权限新增、编辑和归档隐藏。
- 子任务更新页可恢复草稿，提交后进入会议看板和历史链路。
- 旧每周更新菜单不再显示，旧路由跳转到子任务执行。

## 8. V1.4 部门任务编辑和子任务状态修订

目标：补齐部门级任务维护能力，并把子任务更新入口调整为更明确的执行状态流。

版本号：`1.4.0`。

主要事项：

- 母任务详情页支持新增、编辑和归档隐藏部门级任务。
- 部门任务总览将待拆解入口改为“拆解”，可直接新增有效子任务。
- 子任务执行页移除所属母任务列，只聚焦子任务、部门级任务和本周更新状态。
- 子任务更新页支持待开启、进行中、已更新、待更新和已完成状态流。
- 修复子任务更新页直达时空白的问题，增加加载、无权限和不存在提示。

交付标准：

- 部门级任务可按权限新增、编辑多负责部门、负责人和截止日期，并可归档隐藏。
- 待拆解部门任务新增子任务后，待拆解数量自动扣减。
- 新分配子任务必须先开启后才能填写更新，完成后锁定更新表单。

## 9. V1.5 会议看板和历史时间线修订

目标：把会议看板提升为第一入口，形成管理会议可直接使用的汇总视图，并把历史时间线改为按周展开的任务矩阵。

版本号：`1.5.0`。

主要事项：

- 取消工作台和风险与逾期独立菜单，会议看板作为系统第一入口。
- 会议看板拆分为总览、母任务看板和部门看板三个独立路由。
- 总览页提供指标卡、柱图、饼图、折线图、简版甘特图和风险逾期汇总。
- 历史时间线改为只读树状周矩阵，按母任务、部门级任务、子任务展开。
- 子任务新增启动时间，用于历史矩阵横向周列和后续状态联动。

交付标准：

- 登录和根路径默认进入会议看板总览。
- 管理层能从会议看板查看本周更新、风险、逾期和任务节奏。
- 历史时间线能按可读权限展示子任务周更新，不提供编辑入口。

## 10. V2 飞书真实接入阶段

目标：2.x.x 全部围绕飞书展开，把飞书从 1.x 的 open_id 和模拟记录预留升级为真实触达、身份入口、卡片回调、组织/人员辅助同步和后续飞书任务生态联动。Web 仍是复杂操作主界面，飞书是提醒、入口和轻量处理层。

### 10.1 V2.0.0 飞书出站消息第一版

版本号：`2.0.0`。

主要事项：

- 参考现有飞书桥接系统的 tenant token 缓存、企业应用配置和消息发送方式。
- 新增飞书企业自建应用配置：app_id、app_secret、API 地址、token 刷新提前量和请求超时。
- 新增飞书诊断接口，用于确认配置是否完整、tenant_access_token 是否可获取。
- 将通知记录从纯模拟升级为可真实发送：支持 `sent`、`failed`、`blocked`、`mock_sent` 等状态。
- 新增按子任务执行人 open_id 发送本周未更新提醒卡片，卡片按钮跳转 Web 周更新页。
- 未绑定 open_id、未启用飞书、配置缺失或接口异常时，必须在通知记录中保留明确阻塞/失败原因。

交付标准：

- 管理员可在通知记录页执行飞书诊断。
- 管理员可从通知记录页触发本周周更新飞书提醒。
- 已绑定 open_id 的执行人能收到周更新提醒卡片。
- 未绑定 open_id 的人员不会误发，通知记录显示 `blocked`。
- 飞书发送异常不会中断整批提醒，失败结果可追踪。

### 10.2 V2.0.1 飞书本地实测和手动绑定

版本号：`2.0.1`。

主要事项：

- 将本地测试环境配置为局域网访问地址，卡片按钮先跳转 `http://10.10.11.229:8080`。
- App ID/Secret 写入本地未跟踪 `.env`，不进入 Git 跟踪文件。
- 人员新增和编辑支持管理员手动录入 open_id。
- 新增测试卡片发送入口，用于先验证指定人员的飞书触达和 Web 跳转。
- open_id 保存前去除首尾空格，空字符串视为解绑，非空值必须全局唯一。

交付标准：

- 管理员能为自己的人员记录手动绑定 open_id。
- 飞书诊断能使用本地 `.env` 配置获取 tenant_access_token。
- 指定测试人能收到 2.0.1 测试卡片，并从卡片打开局域网系统地址。

### 10.3 V2.0.2 多人手动测试

版本号：`2.0.2`。

主要事项：

- 继续采用手动 open_id 绑定，为少量测试人员扩展真实提醒验证。
- 飞书卡片按钮改为服务端签名入口，验证通过后自动创建 session 并跳转业务页面。
- 签名链接包含目标用户、open_id、目标路径、过期时间和随机 nonce，不信任裸 URL 参数里的 open_id。
- 观察多人测试中的 open_id 冲突、权限边界、卡片打开率和提醒记录。
- 根据测试反馈调整卡片文案、按钮入口和通知记录展示。

交付标准：

- 刘星科可收到 2.0.2 测试卡片。
- 刘星科在无系统账号密码、无旧登录态的浏览器中点击卡片后可直接进入系统。
- 签名无效、过期、用户停用或 open_id 不匹配时不能创建 session。

### 10.4 V2.0.3 飞书免登绑定

版本号：`2.0.3`。

主要事项：

- 人员档案新增手机号字段，由管理员维护。
- 后台批量调用飞书通讯录接口，通过手机号解析并预绑定 open_id，解决未绑定人员无法被卡片触达的问题。
- 接入飞书网页免登入口，通过 code 换 user_access_token，再获取 open_id 创建系统 session。
- open_id 已绑定时直接登录；未绑定但手机号唯一匹配时绑定后登录。
- 手机号、姓名或 open_id 冲突时阻塞待人工处理，不自动覆盖已有绑定。

交付标准：

- 管理员可批量解析已录入手机号但未绑定 open_id 的人员。
- 已绑定 open_id 的人员可继续通过 2.0.2 签名卡片免密码进入。
- 用户可从登录页点击“飞书免登”进入系统。
- 冲突、未匹配、停用账号、state 过期或 code 无效时不能创建 session。

### 10.5 V2.0.4 邮箱预绑定、多人任务关系和生产内网端口

版本号：`2.0.4`。

主要事项：

- 删除手机号字段，改为人员邮箱字段。
- 支持上传包含 `姓名`、`邮箱` 的导出文件，按姓名匹配人员并写入邮箱。
- 通过飞书 `contact/v3/users/batch_get_id` 的 `emails` 参数批量解析 open_id。
- 母任务负责人、部门任务负责人、子任务负责人、子任务执行人支持多人。
- 多执行人子任务按执行人分别提交周更新、分别接收飞书提醒。
- Docker 生产内网入口端口通过 `TASK_FOLLOW_DOCKER_HTTP_PORT=28081` 指定，外网反代由 IT 配置。

交付标准：

- 邮箱导入冲突不自动覆盖，返回可读 blocked/conflict 明细。
- 多人负责人/执行人可搜索选择并以标签形式展示。
- 普通执行人只能提交自己的周更新，管理员可代填指定执行人的周更新。
- `/api/health` 返回 `version=2.0.4`。

- 对比飞书返回身份和系统内人员档案，但部门、角色和任务权限仍以系统内配置为准。
- 增加绑定审计、解绑记录和离职/停用人员处理流程。

### 10.12 V2.2 飞书卡片回调和按身份卡片

主要事项：

- 接入飞书卡片回调验签、事件解析和幂等处理。
- 按执行人、任务负责人、管理层、信息中心推送不同卡片。
- 支持轻量确认、打开指定任务、跳转会议看板和记录点击。

### 10.13 V2.3 飞书数据生态联动

主要事项：

- 从现有 Base 或历史快照导入任务、子任务、周更新和附件索引。
- 建立历史数据清洗、字段映射和导入校验流程。
- 按需与日报、周报、飞书任务中心做单向或双向集成。
- 增强飞书推送、回调、点击、处理结果和异常的审计日志。
- 根据真实使用反馈优化飞书卡片效率和权限矩阵。

交付标准：

- 关键飞书触达链路可诊断、可审计、可重试。
- 用户能从飞书进入对应 Web 页面完成复杂操作。
- 飞书生态数据接入不破坏系统内任务模型和权限模型。
- 系统具备长期运维所需的飞书异常处理和审计能力。

## 11. 暂缓事项

以下事项不进入 V1，待核心模型稳定后再评估：

- 自动生成并提交正式周报。
- 自动同步日报系统。
- 飞书任务中心深度双向同步。
- 复杂绩效考核和组织评分规则。
- 面向外部客户或跨公司协作的权限模型。
