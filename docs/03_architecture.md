# 公司工作任务跟踪系统技术架构

## 1. 文档用途

本文档用于描述公司工作任务跟踪系统的初版技术架构、核心模块、数据对象、权限思路、飞书接入和部署方向。本文档是初版方案，后续进入开发前需要补充接口和数据库细节。

## 2. 架构目标

- 支持全公司长期使用，而不是一次性表格工具。
- 支持任务历史长期保存和按任务时间线查看。
- 支持细粒度权限控制，覆盖角色、部门、负责人和执行人关系。
- 支持飞书机器人提醒和 Web 页面主操作入口。
- 支持通过反向代理对内外部办公场景提供安全访问。
- 支持附件存储到公司 NAS，避免把大文件压在数据库内。

## 3. 技术栈初选

| 层级 | 技术方向 | 说明 |
| --- | --- | --- |
| 后端 | FastAPI + SQLAlchemy 2.x + Pydantic + Alembic | 提供业务 API、权限校验、模拟飞书通知、后台任务 |
| 数据库 | PostgreSQL | 存储用户、部门、任务、周更新、事件、通知记录 |
| 前端 | React + TypeScript + Vite + Ant Design，预留 ProComponents | 满足企业后台表格、表单、看板和权限页体验 |
| 飞书接入 | 1.0.0 预留 open_id + 模拟通知 | 真实机器人发送、组织同步和卡片回调放到后续 |
| 附件 | 本地目录优先，预留 NAS 路径 | 1.0.0 本地挂载，后续切换公司 NAS |
| 部署 | Docker Compose + Nginx | 本地优先，后续接公司反向代理和 HTTPS |
| 后台任务 | APScheduler | 支持提醒、逾期检查、同步、导出；1.0.0 不引入 Redis/Celery |

1.0.0 版本号统一记录在根目录 `VERSION`、后端包版本和前端 `package.json` 中。

## 4. 模块划分

### 4.1 身份与组织模块

负责用户、部门、角色和飞书身份绑定。

核心能力：

- 系统管理员可通过账号密码登录，密码只保存不可逆哈希。
- 通过飞书 open_id 识别用户。
- 未绑定 open_id 的普通用户进入时，先按 open_id 匹配；未匹配则按管理员预设姓名精确绑定；仍未匹配则创建待完善人员。
- 维护用户姓名、部门、岗位或系统角色。
- 支持部门负责人、管理层、信息中心等角色配置。
- 为权限模块提供身份和组织上下文。

### 4.2 权限模块

负责判断用户能看什么、能改什么、能导出什么。

权限判断应综合：

- 系统角色。
- 用户所属部门。
- 任务负责人关系。
- 子任务执行人关系。
- 全局查看、部门查看、系统管理等特殊权限。

初版需要覆盖：

- 创建上层任务权限。
- 拆分任务权限。
- 填写周更新权限。
- 查看任务详情权限。
- 查看管理看板权限。
- 导出和系统管理权限。

### 4.3 任务模块

负责任务主数据和状态流转。

核心对象：

- 战略目标。
- 母任务。
- 部门任务。
- 子任务。
- 任务状态。
- 任务优先级。
- 任务负责人和执行人。

任务模块必须由系统生成编号和关联，不允许用户手填关键关联字段。

### 4.4 周更新和历史模块

负责每周填报、任务时间线和历史事件。

核心能力：

- 每周更新作为独立记录保存。
- 支持本周草稿和提交。
- 支持附件关联。
- 支持任务详情按时间线展示周更新、变更、延期、完成等事件。
- 支持过去记录只读或受控更正，避免随意覆盖历史。

### 4.5 看板和会议模块

负责管理层、负责人和会议场景的汇总展示。

核心能力：

- 管理看板展示任务总数、进行中、已完成、延期、有风险、未更新。
- 支持按部门、负责人、状态、时间筛选。
- 支持下钻到任务详情。
- 会议视图集中展示本周重点任务、风险、延期、未更新、已完成和待决策事项。

### 4.6 飞书通知模块

负责机器人提醒、消息卡片和点击记录。

核心能力：

- 按执行人推送本周更新提醒。
- 按任务负责人推送拆分和跟进提醒。
- 按管理层推送会议看板入口。
- 按信息中心推送系统运行状态。
- 记录推送时间、目标用户、卡片类型、发送结果、点击和处理结果。

2.0.0 第一版真实接入边界：

- 采用企业自建应用 `app_id` / `app_secret` 获取 `tenant_access_token`。
- 参考现有飞书桥接系统的 token 缓存和出站消息接口经验，但不复用其会话路由和 FastGPT 业务逻辑。
- 后端新增独立飞书客户端，负责 token 缓存、诊断和 `im/v1/messages` 出站发送。
- 业务层只传入目标用户 open_id、卡片内容和 Web 跳转链接。
- 通知记录必须区分 `sent`、`failed`、`blocked`、`mock_sent`，便于联调和审计。
- 2.0.0 不接飞书长连接、卡片回调和复杂交互，后续 2.x 逐步补齐。

飞书接入通道拆分：

- 企业应用 API 通道：用于机器人消息发送、邮箱解析 open_id、网页免登、后续卡片回调和联系人查询。
- `lark-cli` 通道：保留用于 Base 搜索、字段预览和一次性导入；CLI 不可用时继续给出阻塞反馈。

### 4.7 附件和导出模块

负责周更新附件、历史附件和导出。

核心能力：

- 附件文件存储到公司 NAS。
- 数据库仅保存附件元数据、路径、上传人、关联对象和权限信息。
- 支持按任务、按周、按部门导出数据。
- 支持会议版本或归档快照导出。

## 5. 核心数据对象初稿

| 对象 | 关键字段方向 |
| --- | --- |
| 用户 | username、password_hash、open_id、邮箱、姓名、部门、角色、状态、来源、绑定时间 |
| 部门 | 名称、负责人、上级部门、状态 |
| 战略目标 | 编号、名称、年度、说明、状态 |
| 母任务 | 编号、标题、目标、多人负责人、部门、时间、状态、优先级 |
| 部门任务 | 编号、母任务、部门、多人负责人、时间、状态 |
| 子任务 | 编号、上级任务、多人负责人、多人执行人、计划时间、状态、风险标记 |
| 周更新 | 子任务、执行人、周周期、本周完成、下周计划、风险、附件、提交人、提交时间 |
| 任务事件 | 任务对象、事件类型、操作人、事件内容、发生时间 |
| 通知记录 | 用户、通知类型、卡片类型、发送状态、点击状态、关联任务 |

## 6. 前端架构和体验约束

前端以后台系统和协作工作台体验为主，不做营销页或临时工具页。

基础布局：

- 左侧导航。
- 顶部状态区。
- 主内容区。
- 任务详情使用时间线作为核心展示。
- 看板使用指标、列表、筛选和下钻组合。

视觉和交互约束：

- 中性背景为主，蓝色表示主操作，绿色表示完成，橙色表示待处理，红色表示风险或逾期。
- 卡片只用于任务、统计项和操作模块，不堆叠装饰卡片。
- 表格用于扫描和对比，不作为唯一交互形态。
- 状态标签统一使用待拆分、进行中、待更新、已延期、有风险、已完成等标准状态。
- 页面按身份显示操作，用户看不到自己不能操作的按钮。

初版页面：

- 工作台。
- 战略目标。
- 母任务管理。
- 部门任务。
- 子任务执行。
- 每周更新。
- 会议看板。
- 风险与逾期。
- 历史时间线。
- 通知记录。
- 人员。
- 角色权限。
- Base 同步。
- 任务详情。

## 7. 飞书卡片设计约束

飞书卡片按身份推送，不同用户看到不同入口。

- 执行人卡片：展示待更新任务数量、截止时间、未填写任务摘要，提供“填写进展”和“查看我的任务”入口。
- 任务负责人卡片：展示待拆分任务、未更新执行人、有风险子任务，提供“拆分任务”和“查看负责的任务”入口。
- 管理层卡片：展示总体状态、延期任务数量、风险任务数量、未更新数量，提供“打开会议视图”和“查看风险清单”入口。
- 信息中心卡片：展示填报完成率、机器人推送情况、异常和失败记录，提供“打开系统管理”和“导出本周数据”入口。

飞书卡片只做快速入口和提醒，不承载复杂编辑流程。复杂操作统一跳转 Web 页面。

## 8. 部署架构初稿

当前部署方向：

- 后端服务运行在 Docker Compose 的 `backend` 容器中。
- PostgreSQL 运行在 `postgres` 容器中。
- 附件默认保存到 `data/attachments` 本地挂载目录，服务端保存路径和元数据。
- 前端构建产物运行在 `frontend` 容器中。
- Nginx 作为本地统一入口，2.0.4 生产迁移前默认暴露内网端口 `http://localhost:28081`。
- 2.0.0 通过环境变量启用飞书企业应用出站消息，回调和长连接仍未启用。
- 后台任务负责提醒、逾期检查和导出任务；真实定时推送后续在 2.x 补充。

需要进一步确认：

- 具体服务器位置和资源。
- NAS 挂载路径、权限和备份策略。
- 反向代理域名、证书和访问控制。
- 飞书企业自建应用权限范围。
