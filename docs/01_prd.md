# 公司工作任务跟踪系统产品需求文档

## 1. 文档用途

本文档用于描述公司工作任务跟踪系统的产品目标、用户角色、MVP 范围、核心流程、页面体验和验收口径。技术实现细节见 `03_architecture.md`，验收清单见 `04_acceptance_checklist.md`。

## 2. 背景

当前公司工作任务跟踪主要依赖飞书多维表格完成任务录入、拆分、周更新、提醒和看板展示。多维表格作为过渡工具可以继续使用，但它更适合轻量数据登记和协作，不适合作为长期运行的任务管理系统主链路。

本系统目标不是再做一张表，而是建设一个长期使用的公司工作任务跟踪系统，解决任务从创建、拆分、执行、每周更新、会议查看到历史追踪的完整闭环。

## 3. 当前核心问题

### 3.1 无法按时间线查看任务进展

现有表格每周需要清空部分字段后重新填写，历史只能依赖信息中心留存快照。用户无法直接点开一个任务，连续查看从任务开始到当前每周做了什么、有什么变化、是否延期、风险如何演变。

新系统需要把每周进展作为独立历史记录保存，不再通过清空字段来制造“本周状态”。

### 3.2 编号和关联依赖手填，容易出错

现有任务编号、子任务编号、目标编号等字段依赖人工填写。字段一旦填错，关联关系就可能失效；更麻烦的是，错误操作仍然可能触发自动新增、同步等工作流，带来后续维护成本。

新系统需要由后端统一生成编号、建立关联和校验输入。错误数据不能进入主流程，更不能触发后续动作。

### 3.3 看板和表格展示不适合长期管理

多维表格分组视图、仪表盘和看板视图都难以承载公司级长期任务管理。管理层需要快速看到重点任务、风险、延期、未更新、负责人和部门分布；执行人需要只看到自己要做和要填的内容。

新系统需要提供专门设计的 Web 页面和会议视图，而不是依赖表格分组模拟系统界面。

### 3.4 缺少字段校验和流程校验

多维表格无法充分校验格式、必填项、关联合法性、人员身份、时间范围和重复提交。拆分任务、更新周进度、调整负责人等操作都需要系统级校验。

新系统需要把“先校验，再保存，再触发后续动作”作为基本原则。

## 4. 产品目标

- 长期使用：系统按长期运行设计，不依赖每周清空字段维持状态。
- 低学习成本：全公司使用，普通员工能快速找到自己要填、要看、要处理的内容。
- 全流程可追踪：任务创建、拆分、更新、延期、完成、变更都能留下记录。
- 更细权限：按角色、部门、任务负责人、执行人、管理层和系统管理员分别控制可见和可操作范围。
- 飞书入口友好：通过飞书机器人推送提醒、入口卡片和快捷操作，减少用户主动查找成本。
- 页面可用且好看：面向全公司使用，界面需要正式、清爽、稳定，不做临时工具感页面。

## 5. 用户角色

| 角色 | 主要诉求 |
| --- | --- |
| 总经办会议相关 | 总经理、总经办秘书审阅公司任务推进、风险、逾期和会议决策事项 |
| 部门负责人 | 查看本部门牵头母任务，将母任务拆分到部门级任务，管理与本部门相关的部门任务 |
| 任务负责人 | 承接自己负责的部门任务，拆分子任务、指定执行人并跟踪进展 |
| 子任务执行者 | 执行本人子任务，每周填写进展、遗留事项和下一步计划，发现风险时登记 |
| 观察者 | 在授权范围内只读查看任务、看板和历史进展 |
| 信息中心维护人员 | 维护系统、处理账号和权限、按需导出数据，不单独形成业务使用引导 |

## 6. MVP 范围

第一版先完成任务跟踪核心闭环：

- 上层任务创建：总经办或秘书创建公司级或部门级任务。
- 任务拆分：部门负责人把牵头母任务拆分为部门任务，任务负责人再把部门任务拆成可执行子任务。
- 每周更新：执行人填写本周完成、下周计划、风险问题和附件。
- 任务时间线：点开任务可查看历史每周进展、变更和关键节点。
- 管理看板：管理层查看任务状态、未更新、延期、风险和完成情况。
- 飞书机器人提醒：按用户身份推送待办、填报提醒和看板入口。
- 权限控制：按角色、部门、负责人和执行人控制数据可见性和操作权限。

## 7. 非 MVP 范围

以下能力第一版先预留关联，不强行打通：

- 日报系统自动同步。
- 周报系统自动生成和提交。
- 飞书任务中心双向同步。
- 多维表格实时双向同步。
- 复杂绩效考核或组织考评规则。

这些能力需要在核心任务数据模型稳定后，再按实际使用情况逐步接入。

## 8. 核心用户流程

### 8.1 总经办或秘书创建任务

总经办或秘书在 Web 页面创建战略目标和母任务，选择负责人、牵头部门、时间范围、优先级和说明。系统保存前校验必填项、人员身份和时间合法性，保存后生成任务编号和任务事件。

### 8.2 部门负责人拆分母任务

部门负责人只查看牵头部门为本人所属部门的母任务，并在母任务下建立部门任务、明确负责部门和任务负责人。部门负责人可以管理与本人部门相关或由本人部门牵头母任务下的部门任务，但不能仅凭该身份拆分子任务。

### 8.3 角色化使用引导

使用引导分为首次进入系统的框架引导和首次主动点击左侧板块的专项引导。总经办会议相关引导面向经营会议审阅；观察者引导面向全局只读审阅、任务追溯和多重身份提示；部门负责人引导面向部门承接、任务拆分和闭环跟进；任务负责人引导面向部门任务拆解、执行人指定、周更新跟踪和风险登记；子任务执行者引导面向本人任务执行、周更新提交、风险登记和任务完成。部门负责人、任务负责人或观察者若本人同时承担子任务执行，系统在其存在有效执行任务时提供子任务执行专项引导；任务负责人存在有效负责子任务时，也提供子任务跟踪专项引导。

### 8.4 任务负责人拆分子任务

任务负责人收到待拆分提醒后进入部门任务页，只对自己负责的部门任务创建子任务，选择执行人和计划时间。子任务负责人始终继承部门任务负责人，不单独维护。系统自动生成子任务编号，通过校验后生成子任务和周更新待办。

### 8.5 执行人提交每周更新

执行人在“本周填报”页面或飞书卡片入口进入填报页，只看到自己需要更新的子任务。填报内容包括本周完成、下周计划、风险问题和附件。提交后生成周更新记录，并更新本周状态。

### 8.6 管理层查看看板和会议视图

管理层通过管理看板查看整体状态、风险、延期、未更新和部门分布。周会场景使用会议视图集中查看本周重点任务、需要协调的问题和未更新清单。

### 8.6 信息中心维护系统

信息中心维护用户、部门、角色、权限、机器人推送记录、导出和历史数据导入。日常维护应通过系统完成，减少每周人工救数据。

## 9. 页面体验要求

### 9.1 设计定位

系统面向全公司长期使用，页面不能呈现临时工具感。视觉需要正式、清爽、稳定，既适合管理层会议查看，也适合普通员工每周快速填报。

设计目标：

- 看起来像正式内部系统，而不是表格插件。
- 操作路径短，用户知道自己下一步要做什么。
- 管理层看重点，执行人看待办，负责人看拆分和跟进。
- 页面信息密度适中，避免过度装饰。
- 支持桌面端为主，兼顾出差时笔记本和移动端浏览。

### 9.2 初版页面

| 页面 | 使用对象 | 核心目的 |
| --- | --- | --- |
| 我的任务 | 所有用户 | 查看自己要处理、要填写、要关注的任务 |
| 本周填报 | 执行人 | 快速填写本周完成、下周计划、风险和附件 |
| 任务详情 | 所有有权限用户 | 查看任务信息、子任务、周更新和历史时间线 |
| 任务拆分 | 任务负责人 | 创建和维护子任务，分配执行人和时间 |
| 管理看板 | 管理层或负责人 | 查看整体状态、风险、延期、未更新和完成情况 |
| 会议视图 | 管理层或总经办会议 | 周会集中查看重点任务和问题 |
| 系统管理 | 信息中心或管理员 | 维护用户、角色、权限、导出和配置 |

### 9.3 关键页面要求

- 我的任务：展示本周待更新数量、逾期数量、风险任务数量、待处理事项、我负责的任务和我执行的任务。
- 本周填报：展示本周周期、截止时间、待更新子任务、快速表单、草稿保存、提交校验和附件上传。
- 任务详情：展示基本信息、子任务列表、周更新时间线、风险区、附件和变更历史。
- 任务拆分：展示上层任务信息、子任务编辑区、执行人选择、时间计划和校验结果。
- 管理看板：展示任务总数、进行中、已完成、延期、有风险、未更新、部门分布、重点任务、风险清单。
- 会议视图：一页内支持查看本周重点任务、本周新增风险、延期和未更新任务、已完成任务、需要会议决策的问题。
- 系统管理：维护用户部门同步、角色权限、推送记录、数据导出、历史导入和系统配置。

### 9.4 交互原则

- 用户进入页面后，不需要理解底层表结构。
- 编号只展示，不要求用户手填。
- 能选择的内容就不让用户输入自由文本。
- 错误在提交前提示，不在自动化触发后补救。
- 页面按身份显示操作，用户看不到自己不能操作的按钮。
- 飞书卡片只做快速入口，复杂操作跳转 Web 页面。

## 10. 飞书入口要求

飞书机器人适合提醒、快捷入口和轻量操作。复杂任务拆分、看板查看、历史时间线和系统管理应通过 Web 页面完成。

初版飞书卡片按身份区分：

| 卡片 | 目标用户 | 内容 | 主要按钮 |
| --- | --- | --- | --- |
| 本周任务更新 | 子任务执行人 | 待更新数量、截止时间、未填写任务摘要 | 填写进展、查看我的任务 |
| 任务拆分与跟进 | 任务负责人 | 待拆分任务、未更新执行人、有风险子任务 | 拆分任务、查看负责的任务 |
| 本周任务看板 | 管理层 | 总体状态、延期数量、风险数量、未更新数量 | 打开会议视图、查看风险清单 |
| 任务系统运行状态 | 信息中心 | 填报完成率、推送情况、异常记录 | 打开系统管理、导出本周数据 |

## 11. 关键口径

### 11.1 新系统不再依赖周日清空留存

原先周日留存主要是因为多维表格需要清空本周字段。新系统中，每周更新天然作为历史记录保存，因此不再需要为了清空而留存。

系统仍可支持按周导出、生成会议版本或归档快照，但这是管理需要，不是主流程补救。

### 11.2 Base 继续作为过渡工具

多维表格可以在新系统上线前继续作为过渡工具使用。新系统上线后，Base 可作为导出展示、历史迁移或临时备份使用，不再作为主业务系统。

### 11.3 飞书是入口，不是唯一界面

飞书机器人适合提醒、快捷入口和轻量操作。复杂任务拆分、看板查看、历史时间线和系统管理应通过 Web 页面完成。

## 12. 验收标准摘要

- 用户能在一个入口看到自己需要处理的任务和本周填报项。
- 管理层能看到本周整体状态、风险、延期和未更新情况。
- 任意任务能查看历史每周进展，不依赖人工快照。
- 编号、关联、人员和时间字段由系统校验，不允许错误数据进入主流程。
- 飞书机器人能按身份推送不同卡片。
- 页面视觉达到公司级内部系统使用标准，不呈现临时工具感。
