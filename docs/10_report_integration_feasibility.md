# 4.5.6 待归类事项与周报中心收尾版

## 1. 文档用途

本文档用于给总经办、人事和系统建设侧统一口径：周报材料和任务跟踪系统可以怎样连接，哪些能力可以先做，哪些能力不进入系统建设范围。

4.5.6 在 4.5.5 基础上完成 4.5.x 收尾：复核工作台、待归类事项、周报中心、部门负责人视图、手机端和空状态，确认 `4.2.1task.md` 主线闭合。系统只生成内部周报快照和可复制文本，不做飞书原生汇报回写。

## 2. 结论摘要

- 系统内生成个人周报可行，可以把子任务周更新、附件、遗留事项、风险项和待归类事项汇总成个人工作材料。
- 待归类事项只服务四类对象：挂载已有部门任务、本部门常态化工作、跨部门协作任务、周报补充记录。
- 正式任务统计仍只来自战略目标、母任务、部门任务、子任务和周更新；待归类事项未转成正式子任务前不进入会议看板正式任务指标。
- 4.5.3 已下线此前延展出的缺任务诉求和上提入口，历史字段仅作兼容保留，不再产生新数据。
- 4.5.4 已增加部门负责人本周周报材料统计，按部门任务补充、本部门常态化、跨部门协作和周报补充四类事项展示数量、状态和最近记录。
- 4.5.6 已确认 4.5.x 主线闭合：四类待归类事项、责任人处理、部门负责人统计和周报复制输出均已进入收尾状态。
- 工作台作为个人行动入口，按多身份叠加展示模块；会议看板保留为公司任务审阅入口，不新增独立会议处理系统。
- 系统不做飞书原生汇报回写；周报输出以系统内快照和可复制文本为准。
- 导出文档不面向执行人；后续如做导出，应面向观察者/人事，按人员和周次生成绩效评判材料，并单独规划。

## 3. 主线与辅助线

系统正式任务主线保持不变：

```text
战略目标 -> 母任务 -> 部门任务 -> 子任务 -> 周更新 -> 历史记录 -> 会议看板
```

待归类事项辅助线固定为：

```text
待归类事项 -> 部门任务补充 / 部门常态化工作 / 跨部门协作 / 周报补充 -> 周报中心 -> 周报材料生成
```

这条辅助线不反向创建母任务或部门任务。只有“挂载已有部门任务”的事项在负责人确认后，必要时可转成正式子任务；转成子任务后才进入正式任务体系。

## 4. 四类待归类事项口径

| 归类方式 | 提交时额外信息 | 处理结果 |
| --- | --- | --- |
| 挂载已有部门任务 | 选择本人所属部门的部门任务 | 经部门任务负责人确认后成为部门任务补充记录；必要时可转正式子任务 |
| 本部门常态化工作 | 默认使用提交人所属部门 | 经部门负责人确认后进入个人周报和部门常态化记录，不进入任务进度 |
| 跨部门协作任务 | 选择协作部门 | 提交部门和协作部门负责人双确认后进入个人周报和协作记录 |
| 周报补充记录 | 无 | 作为个人周报补充材料，不进入正式任务树 |

关闭、退回和撤回均保留事件追溯；已退回、已关闭、已撤回事项不进入后续周报草稿。

## 5. 工作台定位

工作台是个人行动入口，按角色组合叠加模块，而不是只展示最高角色。当前已覆盖执行者、任务负责人、部门负责人相关模块：

- 执行者：待更新子任务、草稿、临近截止、风险登记、周报中心。
- 任务负责人：待处理待归类事项、部门任务补充确认、必要时转正式子任务。
- 部门负责人：本部门任务推进、本部门常态化记录、部门任务补充记录、未更新、风险和逾期。
- 管理员：只作为审计和兜底处理角色，不作为业务默认责任人；管理员运营工作台留到 4.6.x。

总经办/秘书暂不新增新的待归类事项处理对象；继续使用会议看板审阅公司级任务、风险、逾期和更新情况。

## 7. 后续版本建议

- 4.6.x：管理员运营工作台。只做通知失败、人员信息缺失、系统配置风险、同步异常和权限风险等系统运营事项。

## 8. 产品纪律

- `4.2.1task.md` 是待归类事项和周报中心的最高指导口径。
- 任何超出四类待归类事项的新对象或新流程，例如任务缺口对象、会议处理流、主管审批流，都必须先向用户确认。
- 不把人事周报材料需求反向扩展成复杂任务治理系统。
- 生产通知继续保持暂停口径；本线不顺手恢复通知。

## 9. 飞书边界

系统不做飞书原生汇报回写。飞书绩效或人事材料需要的导出能力，后续按“观察者/人事按人员和周次导出绩效材料”单独规划，不混入执行人周报中心。
