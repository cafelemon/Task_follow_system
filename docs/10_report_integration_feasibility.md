# 5.0.0 周报材料与待归类事项边界版

## 1. 文档用途

本文档用于给总经办、人事和系统建设侧统一口径：周报材料和任务跟踪系统可以怎样连接，哪些能力可以先做，哪些能力不进入系统建设范围。

4.7.1 至 4.7.3 在工作台三入口和观察者月度周报 Excel 导出基础上，完成总经办/秘书、部门负责人、任务负责人、执行者和观察者的使用指南更新，并将前端使用指南模块从 `App.tsx` 拆到 `features/guides`。4.7.4 在四类待归类事项上增加责任人个人审批与通知设置。5.0.0 作为生产同步包，随包附带当前数据库快照并恢复系统级通知开启口径。系统只生成内部周报快照、可复制文本和观察者 Excel 材料，不做飞书原生汇报回写。

## 2. 结论摘要

- 系统内生成个人周报可行，可以把子任务周更新、附件、遗留事项、风险项和待归类事项汇总成个人工作材料。
- 待归类事项只服务四类对象：挂载已有部门任务、本部门常态化工作、跨部门协作任务、周报补充记录。
- 正式任务统计仍只来自战略目标、母任务、部门任务、子任务和周更新；待归类事项未转成正式子任务前不进入会议看板正式任务指标。
- 4.5.3 已下线此前延展出的缺任务诉求和上提入口，历史字段仅作兼容保留，不再产生新数据。
- 4.5.4 已增加部门负责人本周周报材料统计，按部门任务补充、本部门常态化、跨部门协作和周报补充四类事项展示数量、状态和最近记录。
- 4.5.6 已确认 4.5.x 主线闭合：四类待归类事项、责任人处理、部门负责人统计和周报复制输出均已进入收尾状态。
- 工作台作为个人行动入口，按多身份叠加展示模块；4.6.x 要把工作台压缩为一屏摘要和跳转入口，详细信息回到业务页面处理。
- 4.6.1 已先将完整待归类事项处理面板和部门负责人详细面板默认收起，保留功能但不占据首屏。
- 4.6.2 已将执行者模块拆为独立组件，按草稿、临近截止、待更新、风险入口优先展示最多 3 个重点任务。
- 4.6.3 已将任务负责人模块拆为独立组件，按可转子任务、待处理事项、可拆解部门任务、待跟进子任务优先展示最多 3 个重点项。
- 4.6.4 已将部门负责人模块拆为独立组件，按风险/逾期、未更新、待拆部门任务、部门任务补充记录、本周材料异常优先展示最多 3 个重点项。
- 4.6.5 已统一三张角色卡视觉密度、手机端可用性和折叠区文案。
- 4.6.6 已将待归类事项升为首屏第一张独立入口卡，并将首屏顺序修正为待归类事项、子任务执行周更新、拆解入口。
- 4.7.0 已新增观察者月度 Excel 导出，面向人事/观察者按人员和周次查看周报材料。
- 4.7.1 已完成总经办/秘书指南更新和指南模块拆分。
- 4.7.2 已完成部门负责人和任务负责人指南更新，且不提升 guide version。
- 4.7.3 已完成执行者和观察者指南更新，且不提升 guide version。
- 4.7.4 已新增待归类事项个人飞书通知和自动同意设置，默认全部关闭；5.0.0 起生产系统级通知恢复开启，个人通知开关仍由责任人自行配置。
- 5.0.0 生产同步包包含当前数据库快照，用于把 4.8.x 已补齐的历史周更新同步到生产环境。
- 4.6.x 当前首屏只保留待归类事项、子任务执行周更新、拆解入口三个行动入口；管理员运营工作台和总经办工作台均暂缓，不进入本轮。
- 系统不做飞书原生汇报回写；周报输出以系统内快照、可复制文本和观察者 Excel 为准。
- 导出文档不面向执行人；4.7.0 的导出仅面向观察者/人事，按月份生成绩效评判材料。

## 3. 主线与辅助线

系统正式任务主线保持不变：

```text
战略目标 -> 母任务 -> 部门任务 -> 子任务 -> 周更新 -> 历史记录 -> 会议看板
```

待归类事项辅助线固定为：

```text
待归类事项 -> 部门任务补充 / 部门常态化工作 / 跨部门协作 / 周报补充 -> 周报中心 -> 周报材料生成
```

这条辅助线不反向创建母任务或部门任务。只有“挂载已有部门任务”的事项在负责人确认后，必要时可转成正式子任务；转成子任务后才进入正式任务体系。

## 4. 四类待归类事项口径

| 归类方式 | 提交时额外信息 | 处理结果 |
| --- | --- | --- |
| 挂载已有部门任务 | 选择本人所属部门的部门任务 | 经部门任务负责人确认后成为部门任务补充记录；必要时可转正式子任务 |
| 本部门常态化工作 | 默认使用提交人所属部门 | 经部门负责人确认后进入个人周报和部门常态化记录，不进入任务进度 |
| 跨部门协作任务 | 选择协作部门 | 提交部门和协作部门负责人双确认后进入个人周报和协作记录 |
| 周报补充记录 | 无 | 作为个人周报补充材料，不进入正式任务树 |

关闭、退回和撤回均保留事件追溯；已退回、已关闭、已撤回事项不进入后续周报草稿。

## 5. 工作台定位

工作台是个人行动入口，按角色组合叠加模块，而不是只展示最高角色。4.6.x 的工作台不再承载完整明细，只保留摘要、最紧急 2 条和跳转入口。4.6.6 后首屏固定为三类行动入口：

- 待归类事项：提交待归类事项、处理待归类事项、查看周报中心，并展示我的提交、待我处理、可转子任务和待确认轻量数量。
- 子任务执行周更新：待更新、草稿未提交、临近截止、可登记风险，以及进入子任务执行和周报中心的入口。
- 拆解入口：待处理事项、可转子任务、负责部门任务、待拆子任务，以及进入待归类事项处理、部门任务和子任务执行的入口。

部门负责人完整信息保留在工作台下方折叠面板，不再占据首屏第三列。卡片按实际可见数量自动填满行宽。

总经办/秘书暂不新增新的待归类事项处理对象；继续使用会议看板审阅公司级任务、风险、逾期和更新情况。

## 7. 后续版本建议

- 管理员运营工作台和总经办工作台继续暂缓到后续单独规划。
- 后续若继续优化工作台，应先明确是否仍保持“入口化”原则，避免重新堆叠完整明细。
- 后续若继续优化角色使用指南，应在 `frontend/src/features/guides/` 下按角色文件更新，不再把 Tour 文案和状态机写回 `App.tsx`。

## 8. 产品纪律

- `4.2.1task.md` 是待归类事项和周报中心的最高指导口径。
- 任何超出四类待归类事项的新对象或新流程，例如任务缺口对象、会议处理流、主管审批流，都必须先向用户确认。
- 不把人事周报材料需求反向扩展成复杂任务治理系统。
- 5.0.0 起生产系统级通知恢复开启；个人待归类事项通知开关仍默认关闭，需要责任人主动开启。

## 9. 自动审批与通知边界

4.7.4 的自动审批与飞书通知只是在四类待归类事项处理链上增加责任人个人开关：

- 自动审批是责任人个人选择，默认关闭，不做部门统一配置或系统默认启用。
- 自动审批只把事项确认成补充记录或协作记录，不自动转子任务、不创建母任务或部门任务、不改变正式任务统计。
- 跨部门协作必须提交部门侧和协作部门侧分别自动或人工确认后，才最终变为已确认。
- 已自动同意事项允许触发责任人或管理员撤销回待确认，并保留事件记录。
- 飞书通知使用现有通知记录、签名链接、点击追踪和去重机制；生产通知总开关、open_id、白名单和停用用户规则继续生效。

## 10. 飞书边界

系统不做飞书原生汇报回写。飞书绩效或人事材料需要的导出能力，当前以 4.7.0 的“观察者/人事按月份导出 Excel”承接，不混入执行人周报中心，也不作为飞书原生汇报提交能力。

## 11. Base 快照回填边界

4.8.0 的 Excel 回填只用于修复系统临时停用周的历史周更新缺口，不恢复 Base 作为主业务系统的定位：

- 回填范围固定为 `2026-W24` 的 `04_周更新进度` 本周内容。
- `03_部门拆解任务` 仅用于辅助匹配原始子任务编号，不用于新建或改写任务结构。
- 已有系统周更新不覆盖，匹配失败不兜底写入。
- 历史附件文件名不创建附件记录；后续真实附件仍以系统上传为准。
- 回填不改变子任务状态、进度、任务树和会议看板正式统计。

## 12. 总经办使用指南边界

4.7.1 后，总经办/秘书的使用指南与当前工作台定位保持一致；4.7.2 和 4.7.3 继续按角色补齐部门负责人、任务负责人、执行者和观察者的当前口径：

- 工作台是进入系统后的行动入口，用于快速进入待归类事项、子任务执行周更新和拆解入口。
- 会议看板是会议审阅主入口，用于审阅公司任务推进、风险逾期、未更新、部门差异和下钻明细。
- 总经办指南不再出现缺部门任务、缺母任务、上提诉求或飞书回写等已排除口径。
- 所有角色 guide version 已在 4.7.1 提升到 `2`；4.7.2 和 4.7.3 只更新对应角色文案，不再次提升版本。
- 执行者指南聚焦子任务执行周更新、待归类事项、周报中心、附件、风险和完成撤回边界。
- 观察者指南聚焦只读审阅、会议看板审阅顺序、任务追溯和月度周报 Excel 导出。
